How LLMs work, from the ground up

18 min read

#The big picture

A large language model (LLM) is one function: text goes in, and out comes a probability for every possible next piece of text. Everything below explains how that function is built and how it gets its numbers.

To write a reply, the model predicts one token, appends it to the input, and runs again. A 500-word answer takes roughly 700 runs of the same function.

The function is a neural network with billions of adjustable numbers called parameters. Nobody sets them by hand. Training tunes them automatically by showing the network huge amounts of text and nudging every parameter to make the true next token more likely.

#Neurons and layers

A neuron is a tiny function: multiply each input by a weight, add them up, add a bias, and pass the result through a nonlinear function. With inputs x₁ to xₙ, weights w₁ to wₙ, and bias b:

y=σ(∑i=1nwixi+b)=σ(w⋅x+b)y = \sigma\left(\sum_{i=1}^{n} w_i x_i + b\right) = \sigma(\mathbf{w} \cdot \mathbf{x} + b)

The weights and bias are the neuron's parameters, and σ is the activation function. Modern networks mostly use ReLU, which is max(0, z), or smooth versions of it such as GELU. Older networks used the S-shaped sigmoid.

The weighted sum is a dot product, so it measures how well the input lines up with the weight vector. A neuron detects one direction in its input space: large output when the input points that way, little or none otherwise.

#A layer is a matrix multiply

Put m neurons side by side, all reading the same n inputs, and you have a layer. Stack their weight vectors as the rows of an m × n matrix W, and the whole layer becomes one line:

y=σ(Wx+b)\mathbf{y} = \sigma(W\mathbf{x} + \mathbf{b})

Real code has no neuron objects. A layer is a matrix multiply followed by an elementwise function, which is why GPUs, built for fast matrix math, run neural networks so well.

The neuron on the left is one row of W on the right; the whole layer computes all its neurons in a single multiply.

"Fully connected" means every neuron reads every input. A multilayer perceptron (MLP) is a stack of fully connected layers, each one's output feeding the next. "Perceptron" was the 1950s name for a single neuron, and it stuck.

#Neurons versus parameters

Neurons are the units; parameters are the connections between them. A layer from 1,000 inputs to 1,000 outputs has 1,000 neurons but about a million weights. When an LLM is described as having 70 billion parameters, that counts weights, not neurons.

#Why the nonlinearity matters

Without σ, stacking layers gains nothing: W₂(W₁x) is just (W₂W₁)x, a single linear map. The nonlinearity is what lets depth build complicated functions.

With enough neurons, even one hidden layer can approximate any continuous function on a bounded region as closely as you like. This is the universal approximation theorem. In practice, stacking many layers is far more efficient than one very wide layer.

#What "activation" means

Every neuron is computed for every input. "Activates" doesn't mean "gets computed"; it means "outputs a large value."

The weighted sum w·x + b works like a matched filter: it correlates the input against a template, the weight vector, and the bias sets a threshold. ReLU then clips everything below zero. For most inputs the neuron outputs 0, and for a few it outputs something large.

Across a sentence, one neuron's outputs might read 0, 0, 0, 3.4, 0, 0.1. A zero contributes nothing downstream, because the next layer multiplies it by its weights. So each neuron effectively says: "if the input matches my pattern, pass my signal on."

When researchers say a neuron "activates for X," they mean they ran lots of inputs through the network, recorded that neuron's output on each, and found its largest values cluster on X. In LLMs those clusters are often a mix of unrelated things, for reasons covered under "What's going on inside."

#How networks learn

A network learns by repeatedly measuring how wrong it is and nudging every parameter in the direction that makes it less wrong. Three pieces make this work: a loss function, gradients, and an update rule.

#Loss: one number for "how wrong"

The loss function compares the network's output with the right answer and returns a single number, where lower is better. For choosing among categories, including "which token comes next," the standard loss is cross-entropy: the negative log of the probability the network gave the correct answer.

L=−log⁡pcorrectL = -\log p_{\text{correct}}

If the network gave the right answer probability 0.9, the loss is 0.105. At 0.01, the loss is 4.6. Confident mistakes are punished hardest.

#Gradient descent

The gradient of the loss has one entry per parameter: how much the loss would change if that parameter moved slightly. Stepping every parameter a little against its gradient lowers the loss:

θ←θ−η ∇θL\theta \leftarrow \theta - \eta \, \nabla_\theta L

Here θ is all the parameters and η is the learning rate, the step size. Picture a ball rolling downhill on a landscape with one dimension per parameter, which for an LLM means billions of dimensions.

#Backpropagation

Backpropagation computes the gradient efficiently. It is the chain rule from calculus, applied layer by layer from the output back to the input. One backward pass costs about twice as much as the forward pass and yields the gradient for every parameter at once.

#In practice

Training never computes the loss over the whole dataset at once. Each step uses a minibatch, a random sample of examples, to estimate the gradient; this is stochastic gradient descent. LLMs use the Adam optimizer or a close relative, which keeps running averages of each parameter's gradients and gives every parameter its own effective step size.

An LLM training run repeats this loop roughly 100,000 to 1,000,000 times, each step on a batch of millions of tokens.

#Turning text into numbers

Neural networks only do arithmetic, so text must become numbers on the way in, and numbers must become text on the way out. Tokens and embeddings handle the input; logits and softmax handle the output.

#Tokens

Text is split into tokens: common words, pieces of words, punctuation, and spaces. A common method, byte-pair encoding (BPE), starts from single characters or bytes and repeatedly merges the most frequent adjacent pair in its training text into a new token. The result is a fixed vocabulary, typically 30,000 to 200,000 tokens.

Common words get a single token, while rare words are spelled from pieces, so any string can be represented. In English, a token averages about three-quarters of a word. To the model, each token is just an integer ID.

#Embeddings

Each token ID selects one row of an embedding matrix with one row per vocabulary token. That row, a vector of d numbers, is the token's starting representation. In large models d is in the thousands; GPT-3 uses 12,288.

The embedding matrix is learned like every other parameter. Training pushes tokens used in similar ways toward similar vectors, so meaning ends up as geometry. Directions in this space come to encode properties such as plurality, tense, or topic.

#Logits and softmax

On the way out, the model produces one score per vocabulary token, called a logit. Softmax turns the logits into probabilities: exponentiate each one, then divide by the total.

pi=ezi∑jezjp_i = \frac{e^{z_i}}{\sum_j e^{z_j}}

Exponentiating makes every value positive and exaggerates the gaps between them; dividing makes them sum to 1. The same function appears again inside attention.

#Why sequences are hard

A token's meaning depends on other tokens, sometimes far away. "Bank" means different things in "river bank" and "bank account," and a pronoun can point back across paragraphs. A language model needs a way to pull in context from anywhere in the input.

A plain MLP takes a fixed-size input. You could feed it the last 10 tokens side by side, but anything earlier is invisible. The network would also have to learn "the word two back" separately for every position.

Recurrent neural networks (RNNs) read text one token at a time, updating a hidden-state vector as they go. In principle that state carries everything seen so far. In practice, two problems held them back:

  • The whole past has to squeeze through one fixed-size vector, so early details fade.

  • Each step depends on the previous one, so training can't run in parallel across a sequence, which makes scaling slow.

Attention was first added to RNNs for machine translation in 2014, letting the network look back at any earlier word directly. In 2017, the paper "Attention Is All You Need" introduced the transformer, which keeps attention and drops the recurrence. Every position is computed in parallel, and every token can reach any earlier token in a single step.

#Attention

Attention lets each token build a weighted average of information from earlier tokens, with weights that depend on content. A token finds the earlier tokens relevant to it and copies information from them into its own vector.

#Queries, keys, and values

Each token's vector x is multiplied by three learned matrices to make three smaller vectors:

  • Query, q = W_Q x: what this token is looking for.

  • Key, k = W_K x: what this token offers to others.

  • Value, v = W_V x: the information it passes along if selected.

To update token i, compare its query with the key of every token j up to and including i. Each comparison is a dot product, divided by √dₖ, where dₖ is the length of the query and key vectors:

sij=qi⋅kjdks_{ij} = \frac{\mathbf{q}_i \cdot \mathbf{k}_j}{\sqrt{d_k}}

Softmax over j turns the scores into weights that sum to 1. The output is the weighted average of the values:

oi=∑j≤isoftmax⁡j(sij) vj\mathbf{o}_i = \sum_{j \le i} \operatorname{softmax}_j(s_{ij}) \, \mathbf{v}_j

The scaling keeps scores in a workable range. A dot product of dₖ random unit-variance terms has variance dₖ, so dividing by √dₖ brings it back to 1. Without it, softmax saturates into all-or-nothing weights.

#The causal mask

A token may only attend to itself and earlier tokens. Scores for later tokens are set to −∞ before the softmax, so their weights become 0. Otherwise the model could simply read the answer during training, since the answer is the next token.

#In matrix form

Stack every token's query, key, and value as the rows of matrices Q, K, and V. Attention for all positions at once is then a few matrix multiplies, with M the causal mask (0 or −∞):

Attention⁡(Q,K,V)=softmax⁡(QK⊤dk+M)V\operatorname{Attention}(Q, K, V) = \operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}} + M\right) V

Here is the key difference from an ordinary layer: the mixing weights are computed from the input, not stored. Only W_Q, W_K, W_V, and an output matrix W_O are learned. The network decides, separately for each input, which tokens talk to which.

#Multi-head attention

Each block runs many attention heads in parallel, each with its own W_Q, W_K, and W_V and a small dₖ, often 128. Their outputs are concatenated and multiplied by W_O to return to width d. GPT-3 uses 96 heads of 128 dimensions each, and 96 × 128 = 12,288 = d.

Heads specialize during training without being told to. Some attend to the previous token, some track grammatical links like the one above, and some find and copy patterns seen earlier in the text.

#Position

Attention by itself is order-blind: a weighted sum over a set gives the same answer however the set is shuffled. So position has to be added in. The original transformer added fixed sine-wave patterns to the embeddings, and GPT-3 learned one position vector per slot.

Many recent models use rotary position embeddings (RoPE) instead. They rotate each query and key by an angle proportional to its position, at several frequencies. The dot product between two tokens then depends on the distance between them.

#The transformer block

A transformer is a stack of identical blocks, each with an attention sublayer and an MLP sublayer. Every token keeps its own vector, and each block reads that vector and adds a correction to it.

Each token's vector runs down the highlighted line; attention and the MLP each read a normalized copy and add their result back.

#The residual stream

Each sublayer's output is added to its input rather than replacing it:

x←x+Attn⁡(Norm⁡(x))x←x+MLP⁡(Norm⁡(x))\begin{aligned} \mathbf{x} &\leftarrow \mathbf{x} + \operatorname{Attn}(\operatorname{Norm}(\mathbf{x})) \\ \mathbf{x} &\leftarrow \mathbf{x} + \operatorname{MLP}(\operatorname{Norm}(\mathbf{x})) \end{aligned}

Think of each token's vector as a stream flowing up through the network. Attention reads from the streams of earlier tokens and writes into this one, while the MLP reads and writes only this one. Attention is the only place information moves between token positions.

The additions also make deep networks trainable. Gradients flow straight back through the sums, so a 100-block model avoids the vanishing gradients that would cripple a plain 100-layer stack.

#Normalization

Before each sublayer, the vector is normalized: rescaled to a consistent overall size, then multiplied by learned per-dimension gains. This keeps values in a stable range across many blocks. LayerNorm subtracts the mean and divides by the standard deviation; RMSNorm, common in recent models, skips the mean.

#The MLP sublayer

The MLP is a two-layer network applied to each token separately, with the same weights at every position. It expands the vector to about 4d, applies a nonlinearity, and projects back to d:

MLP⁡(x)=W2 σ(W1x+b1)+b2\operatorname{MLP}(\mathbf{x}) = W_2 \, \sigma(W_1 \mathbf{x} + \mathbf{b}_1) + \mathbf{b}_2

Its hidden units are what people usually mean by an LLM's "neurons." Each one pairs a pattern detector (its row of W₁) with a vector it writes into the stream when it fires (its column of W₂). Many recent models use a gated variant called SwiGLU, with three matrices instead of two.

The MLPs hold about two-thirds of a standard transformer's parameters. Research suggests they store much of a model's factual knowledge, while attention moves information between positions.

#The whole model

From text in to probabilities out:

  1. Split the text into tokens.

  2. Look up each token's embedding vector.

  3. Pass the vectors through N blocks, each adding attention and then an MLP to the stream.

  4. Normalize the final vectors.

  5. Multiply by the unembedding matrix to get one logit per vocabulary token.

  6. Apply softmax to get next-token probabilities.

During generation, only the last position's probabilities are used. During training, every position predicts its own next token at once.

#Counting the parameters

Each block has four d × d attention matrices (W_Q, W_K, W_V, W_O), giving 4d² parameters. Its MLP has a d × 4d matrix and a 4d × d matrix, giving 8d². Add the token and position embeddings, and the total is:

N≈12Ld2+(V+nctx) dN \approx 12 L d^2 + (V + n_{\text{ctx}}) \, d

That formula produced the last column of the table, matching every published count to within about 2%. For GPT-3 175B, the blocks contribute 12 × 96 × 12,288² ≈ 173.9 billion and the embeddings about 0.6 billion. Biases and normalization weights add well under 1%.

The point: the entire model is these matrices. There is no hidden database or rulebook; 175 billion numbers in matrices are all there is.

#Neurons versus parameters, at scale

GPT-3 175B has 4 × 12,288 = 49,152 MLP neurons per block, about 4.7 million across 96 blocks. Each neuron connects to 12,288 inputs and 12,288 outputs, so those 4.7 million neurons account for about 116 billion parameters. "Billions of neurons" is a common mix-up; the billions are parameters.

#Compute

A forward pass costs about two floating-point operations per parameter per token. GPT-3 175B therefore needs roughly 350 billion operations to produce each token, before counting the attention over its context.

#Training an LLM

An LLM is trained in two broad stages: pretraining on raw text to predict the next token, then fine-tuning to act as a useful assistant. Nearly all the compute, and most of the knowledge, comes from pretraining.

#Pretraining

The training data is a huge corpus of text: web pages, books, code, and more. GPT-3 trained on 300 billion tokens, and recent models train on trillions. The objective is next-token prediction with cross-entropy loss, so nothing needs labeling by hand; the text supplies its own answers.

The causal mask makes this efficient. One sequence of 2,048 tokens yields 2,048 training examples at once: each position predicts its own next token, seeing only what came before. All positions are computed in a single parallel pass.

The result is a base model: an extremely capable text continuer. Ask it a question and it may answer, or it may continue with more questions, because both are plausible continuations of the text.

#Supervised fine-tuning

Training then continues on curated example conversations: prompts paired with good responses. The loss and mechanics are the same, but the data is far smaller and higher in quality. The model learns the format and role of an assistant.

#Reinforcement learning from feedback

Next, the model's own responses are scored, and it is trained to produce higher-scoring ones. In reinforcement learning from human feedback (RLHF), people compare pairs of responses, and a separate reward model learns to predict their preferences. The LLM is then optimized to score well with that reward model.

Variants replace some human judgments with AI feedback guided by written principles. Others use automatic checks, such as whether code passes its tests or a math answer is correct.

None of these stages changes the architecture. They only change the values of the parameters.

#Generating text

Generation is a loop: run the model, pick a token from the predicted distribution, append it, and repeat. It stops when the model emits a special end-of-sequence token or hits a length limit.

Each pass through the loop adds exactly one token; the KV cache, below, keeps later passes from redoing earlier work.

#Picking the next token

Always taking the single most likely token, called greedy decoding, tends to produce flat, repetitive text. So the token is usually sampled from the distribution, shaped by a few settings:

  • Temperature divides the logits by a number T before the softmax. Below 1 concentrates probability on the top choices; above 1 spreads it out.

  • Top-p (nucleus) sampling keeps the smallest set of tokens whose probabilities add up to p, such as 0.9, and samples only from those.

  • Top-k keeps only the k most likely tokens.

Sampling is why the same prompt can produce different answers.

#The KV cache

Because of the causal mask, the keys and values of earlier tokens never change as new tokens arrive. So they are computed once and stored in a key-value (KV) cache. Each new token needs only its own query, key, and value, plus attention over the cache.

#The context window

The context window is the maximum number of tokens the model can attend over, fixed by how it was built and trained. Attention compares every token with every earlier token, so processing a sequence costs compute that grows with the square of its length. The KV cache also grows with length, which is why long contexts are expensive.

The context is the model's only working memory. Between separate runs nothing is retained, except what is put back into the input.

#What's going on inside

Nobody designs what a trained model's neurons or heads do; those roles emerge from training. Mechanistic interpretability is the research field that tries to reverse-engineer them, and a few findings are now well established.

#Features are directions, not neurons

Models appear to represent concepts as directions in the residual stream's vector space, called features. A model can store far more features than it has dimensions by using directions that are nearly, but not exactly, perpendicular. This is called superposition, studied in Toy Models of Superposition.

Superposition is the leading explanation for polysemantic neurons. In Towards Monosemanticity, one neuron in a small model responded to academic citations, English dialogue, HTTP requests, and Korean text. Sparse autoencoders, a dictionary-learning method, pull such mixtures apart into cleaner features.

The same method has scaled to production models. Scaling Monosemanticity extracted up to 34 million features from a middle layer of Claude 3 Sonnet, including features for famous people, cities, and type signatures in code.

#Circuits

Some behaviors have been traced to circuits of heads working together. The best known is the induction head, described in In-context Learning and Induction Heads. A previous-token head copies each token's predecessor into its stream; the induction head then finds where the current token appeared before and copies what came next.

If "Dr. Okafor" appeared earlier, an induction head helps predict "Okafor" the next time "Dr." appears. The authors present preliminary, indirect evidence that circuits like this drive most in-context learning in large models.

The residual-stream view used throughout this document comes from the same research program, laid out in A Mathematical Framework for Transformer Circuits.

#What remains open

Interpretability so far explains only a fraction of what large models compute. Researchers can't yet read off, from the weights, how a model reaches most of its outputs, or reliably predict where it will fail. People know how to build and train these systems far better than they understand what the trained systems do.
