5 · Backpropagation

From Neurons to Language Models·8 of 29·13 min read

Objectives. After this chapter you can:

  • draw the computational graph of an expression and run the backward pass on it by hand;

  • explain forward and reverse mode, and why a scalar loss calls for reverse mode;

  • derive the four backpropagation equations for an MLP;

  • implement a working reverse-mode autodiff engine;

  • state what backpropagation costs in time and memory.

This chapter is the technical center of the book. Every model that follows is trained by the algorithm described here, unchanged.

#5.1 The problem

Gradient descent needs the gradient of a scalar loss with respect to every parameter. For an LLM that is up to 10^12 partial derivatives, needed millions of times.

Three approaches fail or struggle. Finite differences perturb one parameter at a time, so P parameters cost P + 1 evaluations of the loss: hopeless, and inexact besides. Symbolic differentiation produces formulas that grow explosively with the depth of the expression. Deriving by hand works for one architecture and must be redone for the next.

Automatic differentiation (AD) is the answer. It computes derivatives exactly, to machine precision, by applying the chain rule to the sequence of elementary operations the program actually executed. In its reverse mode it has a remarkable cost guarantee:

Cheap gradient principle. The gradient of a scalar function with respect to all of its inputs can be computed in a small constant multiple of the time needed to evaluate the function, independent of the number of inputs. In practice the multiple is 2 to 3.

A trillion derivatives for the price of about two function evaluations. Without this fact there would be no deep learning.

#5.2 Computational graphs

Any numerical computation can be written as a sequence of elementary operations, each taking earlier results as inputs. Drawn as nodes and edges this is a directed acyclic graph, the computational graph.

Take the squared error of a one-parameter linear model, L = (wx + b − y)², and name each intermediate:

u=w x,v=u+b,r=v−y,L=r2.u = w\,x, \qquad v = u + b, \qquad r = v - y, \qquad L = r^2 .

Forward pass. Evaluate in order. With w = 2, x = 3, b = 1, y = 5: u = 6, v = 7, r = 2, L = 4.

Backward pass. For each node n, define its adjoint as the derivative of the final output with respect to that node, written n̄ = ∂L/∂n. Start from L̄ = 1 and walk the graph in reverse. Each operation converts the adjoint of its output into adjoints of its inputs, using only its own local derivative:

StepOperationLocal ruleValue
1L = r²r̄ = 2r · L̄4
2r = v − yv̄ = r̄, ȳ = −r̄4, −4
3v = u + bū = v̄, b̄ = v̄4, 4
4u = w xw̄ = x · ū, x̄ = w · ū12, 8

Figure 5.1: the graph of the worked example. Each box holds a value from the forward pass. The blue number beside it is its adjoint, obtained by starting from 1 at the loss and applying one local rule per arrow, in reverse.

So ∂L/∂w = 12 and ∂L/∂b = 4, which you can confirm from the closed form 2(wx + b − y)x.

Three things generalize from this toy.

  1. Locality. Each operation needs to know only how to turn its output adjoint into input adjoints. Addition copies the adjoint to both inputs. Multiplication sends each input the adjoint times the other input. Nothing global is required.

  2. Fan-out sums. If a value is used in several places, its adjoint is the sum of the contributions from each use. This is the multivariable chain rule.

  3. Order. A node's adjoint is complete only after every node that uses it has been processed. Reverse topological order guarantees this.

In general, for a node n whose value is consumed by nodes c₁, c₂, ...:

nˉ  =  ∑c ∈ consumers(n)(∂c∂n) ⁣⊤cˉ.\bar n \;=\; \sum_{c \,\in\, \mathrm{consumers}(n)} \Big(\frac{\partial c}{\partial n}\Big)^{\!\top} \bar c .

Each term is a vector-Jacobian product from Section 2.2. Backpropagation is this formula applied to every node in reverse order.

Checkpoint 5.1. For y = x·x + x at x = 3, draw the graph. The node x has three outgoing edges. Run the backward pass and confirm x̄ = 7.

#5.3 Forward mode, reverse mode, and why reverse wins

A computation that is a chain of n steps has a Jacobian that is a product of n local Jacobians:

J  =  Jn Jn−1⋯J2 J1.J \;=\; J_n\, J_{n-1} \cdots J_2\, J_1 .

Matrix multiplication is associative, so the product can be accumulated from either end, and the choice determines the cost.

Forward mode starts at the input. Pick a direction v in input space and compute J₁v, then J₂(J₁v), and so on. One pass gives one directional derivative, a Jacobian-vector product. Getting the full gradient of a function with P inputs takes P passes.

Reverse mode starts at the output. Pick a vector u in output space and compute uᵀJ_n, then (uᵀJ_n)J_(n−1), and so on. One pass gives one vector-Jacobian product. For a function with a single output, taking u = 1 yields the entire gradient in one pass.

Cost for the full JacobianEfficient whenMemory
Forward modeOne pass per inputFew inputs, many outputsNo more than the forward computation
Reverse modeOne pass per outputMany inputs, few outputsMust store every intermediate value

Training has P inputs (the parameters) and one output (the loss). Reverse mode is the only sensible choice, and backpropagation is reverse-mode AD applied to a neural network's loss.

The price is memory. The backward pass visits operations in reverse and needs the values computed in the forward pass: multiplication needs its operands, ReLU needs to know which units were active. So every intermediate must be kept until the backward pass has consumed it. This is why training a network takes far more memory than running it, and why memory, not arithmetic, usually limits the batch size and sequence length you can train with.

If you have met the adjoint method for sensitivities in optimal control or PDE-constrained optimization, this is the same mathematics. The adjoints here are the discrete costates, and the backward pass is the discrete adjoint solve.

#5.4 Backpropagation through an MLP

Specialize to the MLP of Section 4.4. Define the error signal at layer l as the gradient of the loss with respect to that layer's pre-activations:

δ(l)  ≡  ∂L∂z(l).\delta^{(l)} \;\equiv\; \frac{\partial L}{\partial z^{(l)}} .

Applying the identity table of Section 2.2 to z^(l) = W^(l) h^(l−1) + b^(l) and h^(l) = φ(z^(l)) gives four equations.

(BP1)δ(L)=∂L∂z(L)(for softmax with cross-entropy: p−ec)\textbf{(BP1)}\quad \delta^{(L)} = \frac{\partial L}{\partial z^{(L)}} \qquad\text{(for softmax with cross-entropy: } p - e_c\text{)}
(BP2)δ(l)=(W(l+1)⊤ δ(l+1))⊙φ′(z(l))\textbf{(BP2)}\quad \delta^{(l)} = \Big(W^{(l+1)\top}\,\delta^{(l+1)}\Big)\odot \varphi'\big(z^{(l)}\big)
(BP3)∂L∂W(l)=δ(l) h(l−1)⊤(BP4)∂L∂b(l)=δ(l)\textbf{(BP3)}\quad \frac{\partial L}{\partial W^{(l)}} = \delta^{(l)}\, h^{(l-1)\top} \qquad\qquad \textbf{(BP4)}\quad \frac{\partial L}{\partial b^{(l)}} = \delta^{(l)}

Reading them. BP1 starts the recursion at the output, where the error is prediction minus target. BP2 carries the error back one layer: multiply by the transpose of the weights that carried the signal forward, then gate by the activation's derivative. BP3 says each weight's gradient is the error at its output times the activation at its input, the same outer-product form as in Chapter 3. BP4 is the bias case.

The algorithm.

  1. Forward: compute and store z^(l) and h^(l) for l = 1, ..., L. Compute the loss.

  2. Initialize δ^(L) from BP1.

  3. For l = L down to 1: compute the gradients of W^(l) and b^(l) from BP3 and BP4, then, if l > 1, compute δ^(l−1) from BP2.

Cost. The forward pass multiplies by each W^(l) once. The backward pass multiplies by each W^(l)ᵀ once and forms one outer product per layer. Both are proportional to the number of weights, so the backward pass costs about as much as the forward pass.

Batches. With a batch of B examples stored as rows, the activations become matrices H^(l) of shape (B, n_l) and the error signals matrices Δ^(l) of the same shape. The sum over examples turns BP3 into a single matrix product, Δ^(l)ᵀ H^(l−1), and BP4 into a sum of Δ^(l) over its rows. Lab 5A implements exactly this.

#5.5 What the equations say about depth

Unroll BP2 from the output down to the first layer:

δ(1)  =  D(1)W(2)⊤D(2)W(3)⊤⋯D(L−1)W(L)⊤ δ(L),D(l)=diag⁡(φ′(z(l))).\delta^{(1)} \;=\; D^{(1)} W^{(2)\top} D^{(2)} W^{(3)\top} \cdots D^{(L-1)} W^{(L)\top}\, \delta^{(L)}, \qquad D^{(l)} = \operatorname{diag}\big(\varphi'(z^{(l)})\big).

The gradient reaching the first layer is the output error multiplied by a product of L − 1 matrices. If those matrices typically shrink vectors, the product shrinks exponentially with depth and early layers receive almost no signal: the vanishing gradient problem. If they typically stretch vectors, the product grows exponentially: exploding gradients. A deep network trains well only when this product stays near neutral.

This single observation motivates most of the next two chapters. Activation choice controls the D factors. Initialization controls the scale of the W factors at the start. Normalization layers keep the scales in range during training. Residual connections change the product into something that cannot vanish.

#5.6 Automatic differentiation in practice

Nobody derives BP1 through BP4 for a modern architecture. A framework such as PyTorch does what Lab 5B does, at scale.

  • Each tensor operation records, as it runs, which tensors it consumed and a function that computes its vector-Jacobian product. The graph is built dynamically by executing ordinary code, so loops and branches work without special treatment.

  • Calling loss.backward() sorts the recorded graph topologically and runs the VJP functions in reverse, accumulating adjoints into the .grad field of each parameter.

  • Because adjoints accumulate by addition, gradients must be reset to zero before each new backward pass. Forgetting this is a classic bug.

  • For inference, wrapping the code in torch.no_grad() turns off recording, so intermediates are freed immediately and memory use falls.

A framework is, at bottom, a library of array operations, each paired with its VJP, plus this bookkeeping. Three VJPs are worth knowing because they surprise people: a broadcast addition sends back the adjoint summed over the broadcast axes; an indexing operation scatters the adjoint back into the positions it read from; and a matrix product Y = XW sends back X̄ = ȲWᵀ and W̄ = XᵀȲ.

#Lab 5A: backpropagation by hand

A two-layer MLP in numpy, with the backward pass written from the batched forms of BP1 through BP4. It is trained on the spiral data that defeated the linear model in Lab 3.

import numpy as np
from data import make_spiral
from lab02_gradcheck import numerical_grad, rel_error

def softmax(z):
    z = z - z.max(axis=1, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=1, keepdims=True)

def init(d_in, d_hidden, d_out, rng):
    return {
        "W1": rng.normal(size=(d_hidden, d_in)) * np.sqrt(2.0 / d_in),
        "b1": np.zeros(d_hidden),
        "W2": rng.normal(size=(d_out, d_hidden)) * np.sqrt(2.0 / d_hidden),
        "b2": np.zeros(d_out),
    }

def forward(p, X, y):
    n = X.shape[0]
    Z1 = X @ p["W1"].T + p["b1"]          # (n, h)   pre-activations
    A1 = np.maximum(Z1, 0)                # (n, h)   ReLU
    Z2 = A1 @ p["W2"].T + p["b2"]         # (n, k)   logits
    P = softmax(Z2)
    loss = -np.log(P[np.arange(n), y]).mean()
    return loss, (X, Z1, A1, P)

def backward(p, cache, y):
    X, Z1, A1, P = cache
    n = X.shape[0]
    D2 = P.copy(); D2[np.arange(n), y] -= 1; D2 /= n   # BP1: (P - Y)/n
    g = {"W2": D2.T @ A1, "b2": D2.sum(axis=0)}        # BP3, BP4
    D1 = (D2 @ p["W2"]) * (Z1 > 0)                     # BP2
    g["W1"] = D1.T @ X                                 # BP3
    g["b1"] = D1.sum(axis=0)                           # BP4
    return g

if __name__ == "__main__":
    rng = np.random.default_rng(0)
    X, y = make_spiral()

    # 1. Check the analytic gradient against finite differences.
    p = init(2, 8, 3, rng)
    Xc = rng.normal(size=(10, 2)); yc = rng.integers(0, 3, size=10)
    _, cache = forward(p, Xc, yc)
    g = backward(p, cache, yc)
    for name in p:
        num = numerical_grad(lambda _: forward(p, Xc, yc)[0], p[name])
        print(f"grad check {name}: {rel_error(g[name], num):.2e}")

    # 2. Train.
    p = init(2, 64, 3, rng)
    for t in range(3001):
        loss, cache = forward(p, X, y)
        g = backward(p, cache, y)
        for name in p:
            p[name] -= 1.0 * g[name]
        if t % 500 == 0:
            acc = (np.argmax(cache[3], axis=1) == y).mean()
            print(f"step {t:4d}  loss {loss:.4f}  acc {acc:.3f}")

Expected: all four gradient checks report relative error near 1e-10. Training reaches loss 0.03 and accuracy 0.993, against 0.54 for the linear model. One hidden layer, with the features learned, solved a problem no linear model can.

#Lab 5B: an autograd engine

Now the general mechanism. Each Value holds a number, its adjoint, the values it was computed from, and a closure that applies the local rule. This is reverse-mode AD in about fifty lines.

import math, random

class Value:
    """A scalar that remembers how it was computed."""
    def __init__(self, data, parents=(), op=""):
        self.data = data
        self.grad = 0.0
        self._parents = parents
        self._backward = lambda: None     # pushes self.grad to the parents
        self.op = op

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), "+")
        def _backward():
            self.grad += out.grad
            other.grad += out.grad
        out._backward = _backward
        return out

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), "*")
        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward
        return out

    def __pow__(self, k):                 # k is a plain number
        out = Value(self.data ** k, (self,), f"**{k}")
        def _backward():
            self.grad += k * self.data ** (k - 1) * out.grad
        out._backward = _backward
        return out

    def tanh(self):
        t = math.tanh(self.data)
        out = Value(t, (self,), "tanh")
        def _backward():
            self.grad += (1 - t * t) * out.grad
        out._backward = _backward
        return out

    def __neg__(self): return self * -1
    def __sub__(self, other): return self + (-other)
    def __radd__(self, other): return self + other
    def __rmul__(self, other): return self * other
    def __truediv__(self, other): return self * other ** -1

    def backward(self):
        order, seen = [], set()
        def visit(v):                     # depth-first topological sort
            if v not in seen:
                seen.add(v)
                for p in v._parents:
                    visit(p)
                order.append(v)
        visit(self)
        self.grad = 1.0
        for v in reversed(order):         # outputs before inputs
            v._backward()

A small network library on top of it, and a test:

class Neuron:
    def __init__(self, n_in):
        self.w = [Value(random.uniform(-1, 1)) for _ in range(n_in)]
        self.b = Value(0.0)
    def __call__(self, x, nonlin=True):
        z = sum((wi * xi for wi, xi in zip(self.w, x)), self.b)
        return z.tanh() if nonlin else z
    def parameters(self): return self.w + [self.b]

class MLP:
    def __init__(self, sizes):
        self.layers = [[Neuron(a) for _ in range(b)] for a, b in zip(sizes, sizes[1:])]
    def __call__(self, x):
        for i, layer in enumerate(self.layers):
            last = i == len(self.layers) - 1
            x = [n(x, nonlin=not last) for n in layer]
        return x[0] if len(x) == 1 else x
    def parameters(self):
        return [p for layer in self.layers for n in layer for p in n.parameters()]

if __name__ == "__main__":
    # Check against a hand computation: f = (a*b + c)^2 at a=2, b=-3, c=10.
    a, b, c = Value(2.0), Value(-3.0), Value(10.0)
    f = (a * b + c) ** 2
    f.backward()
    print(f.data, a.grad, b.grad, c.grad)     # 16.0 -24.0 16.0 8.0

    # A value used twice must accumulate both contributions.
    x = Value(3.0); y = x * x + x
    y.backward()
    print(x.grad)                             # 7.0

    # Train a 2-4-1 network on XOR.
    random.seed(0)
    X = [[0, 0], [0, 1], [1, 0], [1, 1]]; Y = [0, 1, 1, 0]
    net = MLP([2, 4, 1])
    for step in range(501):
        loss = sum(((net(x) - y) ** 2 for x, y in zip(X, Y)), Value(0.0))
        for p in net.parameters(): p.grad = 0.0
        loss.backward()
        for p in net.parameters(): p.data -= 0.1 * p.grad
        if step % 100 == 0:
            print(f"step {step:4d}  loss {loss.data:.5f}")
    print([round(net(x).data, 2) for x in X])

Expected: the loss falls from 2.7 to below 1e-5 by step 300, and the final predictions are [0.0, 1.0, 1.0, 0.0]. The network that Minsky and Papert showed a perceptron could not learn is learned in a fraction of a second, by an algorithm you now fully understand.
