From Neurons to Language Models·13 of 29·12 min read

Objectives. After this chapter you can:

  • explain what a token is and implement byte-pair encoding;

  • write the autoregressive factorization and the training objective of a language model;

  • build an n-gram model, compute its perplexity, and explain why n-grams hit a wall;

  • explain what an embedding is and why learned vectors generalize where counts cannot.

#9.1 Text as tokens

A network consumes numbers, so text must first become a sequence of integers. Each integer indexes an entry in a fixed vocabulary, and each entry is a token. The choice of what a token is has consequences that reach all the way to the behavior of a finished LLM.

UnitVocabulary sizeSequence lengthProblem
CharactersAbout 100LongThe model must learn spelling before it can learn anything else; long sequences are expensive
WordsHundreds of thousands, and open-endedShortAny word outside the vocabulary cannot be represented; rare words get little training signal
Subwords30,000 to 200,000In betweenToken boundaries are arbitrary with respect to meaning and spelling

Every modern LLM uses subwords. Frequent words are single tokens. Rare words are split into several pieces. Nothing is ever out of vocabulary. As a rough guide for English, a token is about four characters, or three quarters of a word. The ratio varies by tokenizer and is worse for other languages and for code.

#9.2 Byte-pair encoding

Byte-pair encoding (BPE) builds a subword vocabulary from data. It began as a compression algorithm (Gage, 1994) and was adapted for translation by Sennrich and others (2016).

  1. Start with the 256 possible byte values as the vocabulary. Any text in any language is a sequence of bytes, so everything is representable from the outset.

  2. Count every adjacent pair of symbols in the training text.

  3. Replace the most frequent pair everywhere with a new symbol, and add that symbol to the vocabulary.

  4. Repeat until the vocabulary reaches the target size.

To encode new text, convert it to bytes and apply the learned merges in the order they were learned. To decode, expand each symbol back to its bytes.

Lab 9A implements this. Trained on a few repeated sentences about a cat and a mat, the first merges it learns are "at", "th", " th", "at ", "e ", and " the ". Frequent strings become single tokens, with their leading spaces attached.

What tokenization does to a model. Several well-known quirks of LLMs are consequences of this preprocessing step, not of the network.

  • The model never sees letters. It sees token identities. Counting the letters in a word or reversing a string requires knowledge of spelling that the model must infer indirectly.

  • Numbers are split into irregular chunks, which makes digit-by-digit arithmetic harder to learn than it would be on aligned digits.

  • The same word with and without a leading space, or capitalized, is usually a different token.

  • Context limits, speed, and price are all counted in tokens, not characters or words.

Vocabularies also include special tokens that never occur in ordinary text: markers for the start and end of a document, and, in chat models, markers that separate the turns of a conversation (Chapter 14).

#9.3 Language modeling

A language model is a probability distribution over token sequences. By the chain rule of probability (Section 2.3), any such distribution factors exactly as

p(x1,…,xT)  =  ∏t=1Tp(xt∣x<t).p(x_1, \dots, x_T) \;=\; \prod_{t=1}^{T} p\big(x_t \mid x_{<t}\big).

So modeling sequences reduces to one task repeated: given a prefix, predict a distribution over the next token. A model built this way is called autoregressive. Nothing has been assumed or approximated yet.

Training. Parameterize the conditional as p_θ and fit it by maximum likelihood. The loss is the average negative log-probability the model assigns to each actual next token:

L(θ)  =  −1T∑t=1Tlog⁡pθ(xt∣x<t).L(\theta) \;=\; -\frac{1}{T}\sum_{t=1}^{T} \log p_\theta\big(x_t \mid x_{<t}\big).

This is the cross-entropy of Section 3.4, applied at every position, with the vocabulary as the set of classes. During training the model is always given the true prefix, whatever it would have predicted itself; this is called teacher forcing.

Generation. Sample a token from p_θ(· | prefix), append it to the prefix, and repeat. Chapter 15 covers the choices involved.

Two reasons this formulation mattered.

First, the labels are free. The target at each position is just the next token of the text. No annotation is needed, so any text ever written is training data. This is called self-supervised learning, and it is what made training on trillions of tokens possible.

Second, the task is general. Translation is continuing "English: ... French:". Answering a question is continuing the question. Writing a function is continuing its signature and docstring. A sufficiently good next-token predictor is, implicitly, a system for every task that can be posed as text.

#9.4 Perplexity

The standard measure of a language model is perplexity, the exponential of its per-token cross-entropy on held-out text:

PPL  =  exp⁡(L).\mathrm{PPL} \;=\; \exp\big(L\big).

Perplexity is an effective branching factor. A model that is uniformly unsure among k tokens at every step has perplexity k. A model with perplexity 20 is, on average, as uncertain as if it were choosing among 20 equally likely tokens. A perfect model does not reach perplexity 1, because language is not deterministic: the floor is set by the entropy of the text itself.

Perplexities are comparable only between models with the same tokenizer on the same test set. A character-level perplexity of 4 and a subword-level perplexity of 20 measure different things.

Checkpoint 9.1. A model's loss on held-out text is 3.0 nats per token. What is its perplexity? How many bits per token is that? If tokens average four characters, how many bits per character?

#9.5 Counting: n-gram models

The oldest way to estimate the conditionals is to truncate the context and count. An n-gram model assumes the next token depends only on the previous n − 1:

p(xt∣x<t)  ≈  p(xt∣xt−n+1,…,xt−1)  =  count(xt−n+1,…,xt)count(xt−n+1,…,xt−1).p\big(x_t \mid x_{<t}\big) \;\approx\; p\big(x_t \mid x_{t-n+1}, \dots, x_{t-1}\big) \;=\; \frac{\mathrm{count}(x_{t-n+1}, \dots, x_t)}{\mathrm{count}(x_{t-n+1}, \dots, x_{t-1})} .

The count ratio is the maximum likelihood estimate (Problem 9.3). Lab 9B builds the character-level bigram model, n = 2, on a megabyte of Shakespeare.

ModelHeld-out perplexity
Uniform over 65 characters65
Unigram (character frequencies only)28.4
Bigram12.0

A sample from the bigram model reads: "Whan ashe:'thend se! Wine, ges o tilo g is LI ar". It has learned which letters follow which, and nothing more.

N-gram models dominated speech recognition and translation for decades. They fail for three connected reasons.

  1. Sparsity. The number of possible contexts is V^(n−1). For a word vocabulary of 50,000 and n = 3, that is 2.5 billion contexts, each needing its own distribution. Most are never observed, however large the corpus. Unseen events get probability zero unless the counts are smoothed, and a whole literature exists on how.

  2. No sharing. Tokens are atomic symbols. Having seen "the cat sat" a thousand times tells the model nothing about "the dog sat". Every context is learned from scratch.

  3. Short memory. The context cannot grow beyond a handful of tokens before sparsity makes the counts useless. Agreement between a subject and a verb twenty words apart is out of reach.

All three are the curse of dimensionality: the model is a lookup table over a space that grows exponentially, with no notion that nearby entries should be similar.

#9.6 Embeddings

The fix for all three is to stop treating tokens as atoms. Assign each token a vector of d real numbers, its embedding, and make the vectors learnable parameters. The embeddings form a matrix E ∈ R^(V×d), and looking up token i means taking row i.

Now the model's predictions are a smooth function of vectors. If "cat" and "dog" have similar embeddings, whatever the model learns about one transfers to the other automatically. And the model is free to place them close together, because doing so reduces the training loss: they occur in similar contexts, so similar vectors yield good predictions for both.

The neural language model (Bengio and others, 2003) put this to work. Look up the embeddings of the previous n − 1 tokens, concatenate them, pass the result through an MLP, and finish with a softmax over the vocabulary. Embeddings and network are trained together by backpropagation. It beat the best n-gram models, and it assigned sensible probabilities to sequences it had never seen. In hindsight this paper contains the whole plan for modern language modeling, short of an architecture that can use long contexts.

word2vec (Mikolov and others, 2013) showed how much the embeddings themselves capture. It trained vectors alone, with a cheap objective: predict the words near a given word. The resulting geometry was striking. Words with related meanings clustered. Some relations appeared as consistent directions, so that the vector for "king" minus "man" plus "woman" landed near "queen".

Figure 9.1: if the step from "man" to "woman" is the same vector as the step from "king" to "queen", then king − man + woman lands on queen. The picture is an idealization of a pattern that holds approximately.

This reflects the distributional hypothesis from linguistics: words that occur in similar contexts have similar meanings. The analogy results are less clean than the famous examples suggest, and they hold for some families of relations much better than others. The solid finding is still remarkable. Structure that looks semantic emerged from nothing but an objective to predict co-occurring words. Chapter 20 returns to what that does and does not show.

The limitation. A word2vec embedding is one vector per word type. "Bank" gets the same vector beside a river and in a financial report. What is needed is a representation of each token occurrence that depends on its context. Producing such contextual representations is the job of the architectures in the next two chapters.

#9.7 The template for everything that follows

Every neural language model in this book has the same four stages.

  1. Embed. Map each token ID to a vector by table lookup.

  2. Contextualize. Transform the sequence of vectors so that the vector at each position carries information about the tokens before it.

  3. Unembed. Map the vector at each position to V logits with a linear layer.

  4. Normalize and score. Apply softmax to get next-token probabilities; apply cross-entropy against the actual next token.

Stages 1, 3, and 4 never change. The history of language modeling since 2003 is the history of stage 2: a fixed window through an MLP, then recurrent networks, then the Transformer. The input and output embeddings are often the same matrix, a parameter-saving choice called weight tying.

#Lab 9A: a byte-pair tokenizer

from collections import Counter

def train_bpe(text, num_merges):
    """Learn byte-pair merges. Returns the list of merges in order."""
    ids = list(text.encode("utf-8"))            # start from raw bytes: 256 symbols
    merges = []
    for k in range(num_merges):
        pairs = Counter(zip(ids, ids[1:]))
        if not pairs:
            break
        pair = max(pairs, key=pairs.get)        # most frequent adjacent pair
        new_id = 256 + k
        ids = merge(ids, pair, new_id)
        merges.append((pair, new_id))
    return merges

def merge(ids, pair, new_id):
    out, i = [], 0
    while i < len(ids):
        if i + 1 < len(ids) and (ids[i], ids[i + 1]) == pair:
            out.append(new_id); i += 2
        else:
            out.append(ids[i]); i += 1
    return out

def encode(text, merges):
    ids = list(text.encode("utf-8"))
    for pair, new_id in merges:                 # apply merges in training order
        ids = merge(ids, pair, new_id)
    return ids

def decode(ids, merges):
    vocab = {i: bytes([i]) for i in range(256)}
    for (a, b), new_id in merges:
        vocab[new_id] = vocab[a] + vocab[b]
    return b"".join(vocab[i] for i in ids).decode("utf-8", errors="replace")

if __name__ == "__main__":
    text = ("the cat sat on the mat. the cat ate the rat. "
            "the rat sat on the cat. that cat, that mat, that rat. ") * 20
    merges = train_bpe(text, 30)
    vocab = {i: bytes([i]) for i in range(256)}
    for (a, b), n in merges:
        vocab[n] = vocab[a] + vocab[b]
    print([vocab[n].decode() for _, n in merges[:12]])
    ids = encode("the cat sat on that hat", merges)
    print(len("the cat sat on that hat"), "bytes ->", len(ids), "tokens")
    assert decode(ids, merges) == "the cat sat on that hat"
    assert decode(encode("naïve café ☕", merges), merges) == "naïve café ☕"
    print("round trip ok")

Expected: the first merges listed above, then "23 bytes -> 7 tokens", then "round trip ok". The last assertion shows that text the tokenizer never saw, including an emoji, still encodes and decodes exactly, because the base vocabulary is bytes.

#Lab 9B: a bigram model and its perplexity

For this and later labs you need a plain-text file of about a megabyte, saved as input.txt. The labs were run on the widely used "tiny Shakespeare" file, 1.1 MB of public-domain plays. Any similar text works, but your numbers will differ.

import numpy as np

def bigram_counts(ids, V):
    C = np.zeros((V, V))
    np.add.at(C, (ids[:-1], ids[1:]), 1)        # C[a, b] = count of b following a
    return C

def perplexity(ids, P):
    logp = np.log(P[ids[:-1], ids[1:]])
    return np.exp(-logp.mean())

if __name__ == "__main__":
    text = open("input.txt").read()
    chars = sorted(set(text)); V = len(chars)
    stoi = {c: i for i, c in enumerate(chars)}
    ids = np.array([stoi[c] for c in text])
    n = int(0.9 * len(ids)); train, val = ids[:n], ids[n:]

    C = bigram_counts(train, V)
    print(f"V = {V}; uniform perplexity = {V}")
    unigram = np.bincount(train, minlength=V) + 1.0
    unigram /= unigram.sum()
    print(f"unigram val perplexity = {np.exp(-np.log(unigram[val]).mean()):.2f}")
    for alpha in [0.01, 1.0, 100.0]:
        P = (C + alpha) / (C + alpha).sum(axis=1, keepdims=True)   # add-alpha smoothing
        print(f"alpha {alpha:6.2f}: train {perplexity(train, P):.2f}  val {perplexity(val, P):.2f}")

    rng = np.random.default_rng(0)
    P = (C + 0.01) / (C + 0.01).sum(axis=1, keepdims=True)
    i = stoi["\n"]; out = []
    for _ in range(200):
        i = rng.choice(V, p=P[i]); out.append(chars[i])
    print("".join(out))

Measured on the Shakespeare file: unigram 28.43; bigram validation perplexity 12.03, 11.96, and 13.88 for α = 0.01, 1, and 100. Note that a little smoothing helps on held-out data and a lot hurts.
