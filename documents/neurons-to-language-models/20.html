#15.1 The generation loop

A trained model is a deterministic function from a token sequence to a probability distribution over the next token. Generating text means repeating four steps: run the model on the current sequence; take the distribution at the last position; choose a token from it; append the token. The loop ends when the model produces an end-of-sequence token or a length limit is reached.

All randomness in an LLM's output enters at the third step. The decoding strategy, the rule for choosing a token, is outside the model and can be changed freely at run time. It has a large effect on the character of the output.

#15.2 Decoding strategies

Greedy decoding always takes the most probable token. It is deterministic. For short factual answers it is reasonable. For longer text it tends toward bland, repetitive output and can fall into loops.

Beam search keeps the k highest-scoring partial sequences at each step and returns the best complete one. It approximates the single most probable sequence. That is the right goal when the output is tightly determined by the input, as in translation. For open-ended generation it is the wrong goal: the most probable long sequence is typically generic and repetitive, and human-written text is far from maximally probable under any good model (Holtzman and others, 2019; Problem 15.6).

Sampling draws a token at random according to the predicted probabilities. Pure sampling follows the model's distribution faithfully, and it has a weakness. The distribution has a long tail of thousands of tokens that are each very unlikely, whose probabilities are poorly estimated, and whose total mass is not small. Sooner or later a sample lands in the tail, and one bad token can derail what follows. The remaining methods reshape the distribution before sampling.

Temperature divides the logits by τ before the softmax:

pi(τ)  =  exp⁡(zi/τ)∑jexp⁡(zj/τ).p_i(\tau) \;=\; \frac{\exp(z_i / \tau)}{\sum_j \exp(z_j / \tau)} .

Below 1 it sharpens the distribution toward its mode; above 1 it flattens it. As τ approaches 0 it becomes greedy decoding.

Top-k keeps the k most probable tokens, discards the rest, and renormalizes.

Nucleus sampling, or top-p, keeps the smallest set of tokens whose total probability is at least p. Unlike a fixed k, the set adapts: when the model is confident it may contain one or two tokens, and when the model is uncertain it may contain hundreds.

#15.3 Why generation is sequential, and the KV cache

Training computes all positions in parallel because all the tokens are known (Section 11.4). In generation, token t + 1 cannot be computed until token t has been chosen. So generation takes one forward pass per token.

A naive loop reruns the model on the whole sequence each time. That is wasteful, for a reason that follows from the causal mask: the representations of earlier positions never change when later tokens are appended. Position 5 cannot see position 6, so everything computed for position 5 stays valid.

The only things later positions need from earlier ones are their keys and values in each attention layer. So store them. With a key-value cache, each step processes only the newest token: compute its query, key, and value in each layer; append the key and value to the cache; attend from the new query over all cached keys.

Figure 15.1: each square is one query-key comparison in one attention layer. Without the cache the model repeats every earlier row at every step. With it, the keys and values of earlier positions are stored, and only the newest token's row is computed.

No cacheAbout nm + n²/2The whole prefix through every layer
With cachem + nOne position through every layer, plus attention over t cached keys

Lab 15B implements the cache for your Chapter 12 model, confirms it produces identical output, and measures a 3.3-fold speedup when generating 112 tokens. The advantage grows with length.

The cache is large. It holds a key and a value of width d for every position in every layer: 2 L T d numbers per sequence. For L = 32, d = 4096, and T = 8192 in 16-bit precision that is about 4.3 gigabytes for one conversation. Long contexts are expensive at inference mainly because of this memory, not the arithmetic.

Two phases, two prices. Serving a request has two parts. In prefill, the whole prompt is processed in one parallel pass, filling the cache. In decode, tokens are generated one at a time. Prefill handles many tokens per pass; decode handles one. This is why reading input is much faster and cheaper per token than writing output, and why services charge more for output tokens. It is also why the latency you experience has two components: time to the first token, which grows with prompt length, and the rate of tokens after that.

If many requests begin with the same long prefix, such as a fixed set of instructions or a document, the cache for that prefix can be stored and reused. This is prompt caching.

#15.4 Throughput arithmetic

Two first-order estimates are worth being able to do.

Computation. Each generated token costs about 2N floating-point operations for a model with N parameters, plus the attention over the context.

Memory traffic. To produce one token, every weight must be read from memory once. When generating one sequence at a time, the limit is often not arithmetic but how fast weights can be streamed through the processor:

tokens per second  ≲  memory bandwidth (bytes/s)model size (bytes).\text{tokens per second} \;\lesssim\; \frac{\text{memory bandwidth (bytes/s)}}{\text{model size (bytes)}} .

A model of 7 billion parameters at 16 bits is 14 gigabytes. On hardware that can move 100 gigabytes per second, the bound is about 7 tokens per second. Quantized to 4 bits the same model is 3.5 gigabytes and the bound is about 28. This is the main reason quantization speeds up inference on ordinary computers.

Batching. If several sequences are generated together, the weights are read once for the whole batch. Throughput rises almost in proportion to batch size until arithmetic becomes the limit. Serving systems therefore group concurrent requests, trading a little latency for much higher total throughput.

Speculative decodingA small model drafts; the large model checks several tokens in one pass2 to 3 times faster with identical output distribution

Speculative decoding deserves a closer look because it is exact. A small, fast draft model generates k tokens. The large model then scores all k positions in a single parallel pass, as in training. Each drafted token is accepted with a probability that depends on the ratio of the two models' probabilities for it; at the first rejection, a replacement is sampled from a corrected distribution and the rest of the draft is discarded. The acceptance rule is constructed so that the output is distributed exactly as if the large model had generated every token itself (Problem 15.7). When the draft model is usually right, as it is for easy tokens, several tokens are produced for the price of one large-model pass.

#15.6 Constraining the output

Applications often need output in a strict format, such as JSON matching a schema. Asking nicely works most of the time, and most of the time is not enough for a program that will parse the result.

Constrained decoding enforces the format. At each step, determine from a grammar which tokens can legally come next, set the logits of all others to minus infinity, and sample from what remains. The output is then guaranteed to parse. The guarantee is syntactic only: the structure will be valid, and the content can still be wrong.

#15.7 The context window in practice

The model has no memory between calls. Everything it knows about a conversation is the text it is given on this call. A chat application creates the appearance of memory by sending the entire conversation so far, every time.

Three practical consequences follow.

  • The window is finite. When a conversation or document exceeds it, something must be dropped, summarized, or fetched on demand (Chapter 16).

  • Position matters. Models tend to use information at the beginning and end of a long context more reliably than information in the middle (Liu and others, 2023). Capacity to accept a million tokens is not the same as equal attention to all of them.

  • Everything in the window is input. Instructions, retrieved documents, tool results, and user messages are all one token sequence. The model has no hard separation between text to obey and text to merely read. Chapter 17 returns to this.

#Lab 15A: samplers

import torch, torch.nn.functional as F

def sample_next(logits, temperature=1.0, top_k=None, top_p=None):
    """logits: (V,) for one position. Returns a sampled token id."""
    if temperature == 0:                                   # greedy
        return int(torch.argmax(logits))
    logits = logits / temperature
    if top_k is not None:                                  # keep the k largest
        kth = torch.topk(logits, top_k).values[-1]
        logits = logits.masked_fill(logits < kth, float("-inf"))
    if top_p is not None:                                  # keep the smallest set with mass >= p
        sorted_logits, order = torch.sort(logits, descending=True)
        probs = F.softmax(sorted_logits, dim=-1)
        mass_before = torch.cumsum(probs, dim=-1) - probs
        drop_sorted = mass_before >= top_p
        drop = torch.zeros_like(drop_sorted).scatter(0, order, drop_sorted)
        logits = logits.masked_fill(drop, float("-inf"))
    return int(torch.multinomial(F.softmax(logits, dim=-1), 1))

if __name__ == "__main__":
    torch.manual_seed(0)
    logits = torch.log(torch.tensor([0.5, 0.3, 0.15, 0.05]))
    def freq(**kw):
        counts = torch.zeros(4)
        for _ in range(20000):
            counts[sample_next(logits, **kw)] += 1
        return [round(c, 3) for c in (counts / counts.sum()).tolist()]
    print("T=1.0      ", freq())
    print("T=0.5      ", freq(temperature=0.5))
    print("T=2.0      ", freq(temperature=2.0))
    print("top_k=2    ", freq(top_k=2))
    print("top_p=0.8  ", freq(top_p=0.8))
    print("T=0        ", freq(temperature=0))

The output is the table in Section 15.2. In the top-p branch, a token is dropped when the probability mass of the tokens ranked above it already reaches p, so the token that crosses the threshold is kept.

#Lab 15B: a key-value cache

import math, time, torch, torch.nn.functional as F
from gpt import GPT, Config

@torch.no_grad()
def generate_greedy(model, idx, n_new):
    """Reference: recompute the whole prefix for every new token."""
    for _ in range(n_new):
        logits, _ = model(idx)
        idx = torch.cat([idx, logits[:, -1].argmax(-1, keepdim=True)], dim=1)
    return idx

@torch.no_grad()
def generate_cached(model, idx, n_new):
    """Greedy decoding with a key-value cache. Total length must fit in the context window."""
    cfg = model.cfg; H, d = cfg.n_head, cfg.d_model
    cache = [None] * cfg.n_layer            # per layer: keys and values, each (B, H, t, d/H)
    out, new, t_done = idx, idx, 0          # `new` holds the tokens not yet processed
    for _ in range(n_new):
        B, t_new = new.shape
        pos = torch.arange(t_done, t_done + t_new)
        x = model.tok_emb(new) + model.pos_emb(pos)                 # only the new positions
        for l, blk in enumerate(model.blocks):
            q, k, v = blk.attn.qkv(blk.ln1(x)).split(d, dim=2)
            heads = lambda z: z.view(B, t_new, H, d // H).transpose(1, 2)
            q, k, v = heads(q), heads(k), heads(v)
            if cache[l] is not None:                                # append to the stored K, V
                k = torch.cat([cache[l][0], k], dim=2)
                v = torch.cat([cache[l][1], v], dim=2)
            cache[l] = (k, v)
            T = k.size(2)
            att = (q @ k.transpose(-2, -1)) / math.sqrt(d // H)     # (B, H, t_new, T)
            mask = torch.tril(torch.ones(T, T, dtype=torch.bool))[T - t_new:]
            att = F.softmax(att.masked_fill(~mask, float("-inf")), dim=-1)
            y = (att @ v).transpose(1, 2).contiguous().view(B, t_new, d)
            x = x + blk.attn.proj(y)
            x = x + blk.mlp(blk.ln2(x))
        nxt = model.head(model.ln_f(x[:, -1])).argmax(-1, keepdim=True)
        out = torch.cat([out, nxt], dim=1)
        t_done += t_new; new = nxt                                  # next step: one token
    return out

if __name__ == "__main__":
    torch.manual_seed(0)
    model = GPT(Config()); model.load_state_dict(torch.load("gpt.pt")); model.eval()
    prompt = torch.randint(0, 65, (1, 16))
    t0 = time.time(); a = generate_greedy(model, prompt, 112); t1 = time.time()
    b = generate_cached(model, prompt, 112); t2 = time.time()
    print("identical:", torch.equal(a, b))
    print(f"no cache {t1 - t0:.2f}s   cache {t2 - t1:.2f}s   speedup {(t1 - t0) / (t2 - t1):.1f}x")

Measured: identical: True, and 0.33 seconds without the cache against 0.10 with it. The first iteration is the prefill: new is the whole 16-token prompt. Every later iteration processes exactly one token. Notice that the score tensor in the cached version has shape (B, H, 1, T) during decoding, a single row of the attention matrix.
