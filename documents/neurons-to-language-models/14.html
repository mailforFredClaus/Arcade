10 · Recurrent networks

From Neurons to Language Models·14 of 29·9 min read

Objectives. After this chapter you can:

  • write the equations of a recurrent network and explain backpropagation through time;

  • show from the Jacobian product why gradients vanish across time steps;

  • describe the LSTM and explain why its cell state preserves gradients;

  • describe sequence-to-sequence models, their bottleneck, and the first attention mechanism;

  • list the limitations of recurrence that the Transformer removed.

#10.1 The recurrent idea

Stage 2 of the template in Section 9.7 needs a function that turns a prefix of any length into a fixed-size vector. A recurrent neural network (RNN) does this by maintaining a state and updating it one token at a time with the same learned function:

ht  =  tanh⁡(Wh ht−1+Wx xt+b),logitst  =  U ht.h_t \;=\; \tanh\big(W_h\, h_{t-1} + W_x\, x_t + b\big), \qquad \mathrm{logits}_t \;=\; U\, h_t .

Here x_t is the embedding of token t and h_0 is zero. The state h_t is a learned summary of everything up to position t, and the logits computed from it parameterize the distribution over token t + 1.

Two features are attractive. The parameters are shared across time, so the model handles any sequence length with a fixed parameter count. And unlike an n-gram model, the context is in principle unbounded: h_t can depend on x_1. An RNN is a learned nonlinear dynamical system driven by its input.

#10.2 Backpropagation through time

Unroll the recurrence for T steps and you have a feedforward network of depth T in which every layer has the same weights. Backpropagation applies directly, and this application is called backpropagation through time (BPTT). Since each weight is used at every step, its gradient is the sum of its gradients at all steps, by the fan-out rule of Section 5.2.

Figure 10.1: reading left to right is reading forward in time. The state h is the only channel from the past to the future, and a gradient from a late step must travel back along that same chain.

For long sequences, storing every state for the backward pass is expensive. Truncated BPTT carries the state forward indefinitely but backpropagates only through the most recent k steps.

#10.3 Why simple RNNs forget

Section 5.5 showed that gradients through a deep network are products of per-layer Jacobians. An unrolled RNN is a very deep network, and it has the worst version of the problem, because every factor involves the same matrix:

∂hT∂ht  =  ∏k=t+1Tdiag⁡ ⁣(tanh⁡′(zk)) Wh.\frac{\partial h_T}{\partial h_t} \;=\; \prod_{k=t+1}^{T} \operatorname{diag}\!\big(\tanh'(z_k)\big)\, W_h .

Repeated multiplication by one matrix behaves like a power of it. If the factors shrink vectors on average, the product decays exponentially in T − t. If they stretch, it grows exponentially. There is no stable middle for a generic matrix.

The consequence for learning is specific. Suppose predicting token 100 correctly requires information from token 10. The training signal for that dependency is the gradient of the loss at step 100 with respect to what happened at step 10. If it is 10^-20, the optimizer never finds out that the dependency exists.

Lab 10A measures this directly on a randomly initialized network, as the sensitivity of the output at step 99 to the input at earlier steps.

The simple RNN loses fourteen orders of magnitude in fifty steps. Exploding gradients are handled bluntly by clipping (Section 6.5). Vanishing gradients need a change of architecture.

#10.4 The LSTM

The long short-term memory network (Hochreiter and Schmidhuber, 1997) adds a second state vector, the cell state c_t, whose update is additive and controlled by learned gates. Each gate is a sigmoid layer producing values between 0 and 1.

ft=σ(Wf [ht−1,xt]+bf)forget gate: how much old memory to keepit=σ(Wi [ht−1,xt]+bi)input gate: how much new content to writegt=tanh⁡(Wg [ht−1,xt]+bg)candidate contentot=σ(Wo [ht−1,xt]+bo)output gate: how much memory to exposect=ft⊙ct−1+it⊙gtht=ot⊙tanh⁡(ct)\begin{aligned} f_t &= \sigma\big(W_f\,[h_{t-1}, x_t] + b_f\big) && \text{forget gate: how much old memory to keep}\\ i_t &= \sigma\big(W_i\,[h_{t-1}, x_t] + b_i\big) && \text{input gate: how much new content to write}\\ g_t &= \tanh\big(W_g\,[h_{t-1}, x_t] + b_g\big) && \text{candidate content}\\ o_t &= \sigma\big(W_o\,[h_{t-1}, x_t] + b_o\big) && \text{output gate: how much memory to expose}\\ c_t &= f_t \odot c_{t-1} + i_t \odot g_t \\ h_t &= o_t \odot \tanh(c_t) \end{aligned}

Why it works. Look at the cell update. Along the direct path, the derivative of c_t with respect to c_(t−1) is just diag(f_t). There is no weight matrix and no squashing nonlinearity on that path. If the forget gate is near 1, the cell state and its gradient pass through unchanged, for as many steps as the gate stays open.

This is the residual connection of Section 7.3, discovered eighteen years earlier: make the default behavior "copy the state forward" and let the network learn additive modifications. The principle is the same in both. Gradients survive depth when there is an additive identity path.

The third row of the table shows the mechanism. With the forget gate biased open, sensitivity to an input 74 steps back is the same as to one 9 steps back. The second row is a caution: an LSTM at default initialization, with forget gates near one half, also loses the signal, just more slowly. The architecture makes long memory learnable. It does not make it automatic.

The GRU (Cho and others, 2014) is a simplification with two gates and a single state. It performs about as well.

Checkpoint 10.1. An LSTM's forget gate holds a constant value of 0.9 in every unit. By what factor is the gradient along the cell-state path attenuated over 50 steps? Over 500? What value of the gate would keep the attenuation over 500 steps above one half?

#10.5 Recurrent language models

From about 2010 to 2017, LSTM language models were the state of the art. Lab 10B trains a one-layer character-level LSTM on the Shakespeare text. After 1000 steps its held-out loss is 1.76 nats per character, a perplexity of 5.8, against 12.0 for the bigram model of Lab 9B. Samples from such models produce plausible words, punctuation, and line structure, because the state can track where it is in a word and a line.

#10.6 Sequence to sequence, and the bottleneck

Translation maps one sequence to another of different length. The sequence-to-sequence architecture (Sutskever, Vinyals, and Le, 2014; Cho and others, 2014) uses two RNNs. An encoder reads the source sentence and its final state is taken as a summary. A decoder, initialized from that summary, generates the target sentence token by token.

It worked well enough to challenge decades of hand-built translation systems. It also had an obvious flaw. The whole source sentence, whatever its length, must pass through one fixed-size vector. Quality fell off sharply for long sentences.

#10.7 Attention

Bahdanau, Cho, and Bengio (2014) removed the bottleneck. Keep all the encoder states h_1, ..., h_S, one per source token. At each decoding step, let the decoder compute a weighted average of them, with weights that depend on what it currently needs.

With decoder state d_(t−1):

et,s=score(dt−1,hs),αt,s=exp⁡(et,s)∑s′exp⁡(et,s′),ct=∑s=1Sαt,s hs.e_{t,s} = \mathrm{score}\big(d_{t-1}, h_s\big), \qquad \alpha_{t,s} = \frac{\exp(e_{t,s})}{\sum_{s'} \exp(e_{t,s'})}, \qquad c_t = \sum_{s=1}^{S} \alpha_{t,s}\, h_s .

The score is a small learned function measuring how relevant source position s is to the current decoding step. A softmax turns scores into weights that sum to 1. The context vector c_t is the corresponding average of encoder states, and it is fed to the decoder along with the previous token.

Figure 10.3: line thickness stands for the attention weight. At this step the decoder draws mostly on the second source position. At the next step the weights are recomputed and may point elsewhere.

Three properties made this a turning point.

  • It is a soft lookup. The decoder retrieves information from the source by content, not by position. Because the retrieval is a weighted average and not a hard choice, it is differentiable, and the whole system trains by backpropagation.

  • Path length is one. Any source token can influence any target token through a single attention step, with no chain of recurrent updates between them.

  • It is inspectable. Plotting the weights α shows which source words the model consulted for each target word. For translation the plot looks like a word alignment, learned with no alignment supervision.

It helps to name the parts now. The decoder state acts as a query. Each encoder state acts as both a key, matched against the query, and a value, returned in proportion to the match. Chapter 11 builds everything from this vocabulary.

#10.8 What was still wrong

By 2016 the best systems were LSTMs with attention. Three limitations remained, all from the recurrence.

LimitationCauseEffect
No parallelism within a sequenceh_t cannot be computed before h_(t−1)Training cannot use the full width of a GPU; long sequences are slow
Long paths inside each sequenceInformation between distant tokens of the same sequence still travels step by stepLong-range structure remains hard to learn
A fixed-size running stateEverything about the prefix must fit in h_tThe state is a bottleneck in the decoder and in language models

Attention had been added to recurrent networks as a helper. The question that produced the Transformer was what would happen if the recurrence were deleted and attention did everything.

#Lab 10A: watching gradients vanish

import torch, torch.nn as nn

torch.manual_seed(0)
T, d, h = 100, 16, 64
x = torch.randn(1, T, d, requires_grad=True)

lstm_open = nn.LSTM(d, h, batch_first=True)
with torch.no_grad():                   # PyTorch orders the gates (input, forget, cell, output)
    lstm_open.bias_ih_l0[h:2 * h] = 3.0     # push the forget gate toward 1

for name, rnn in [("RNN (tanh)", nn.RNN(d, h, batch_first=True)),
                  ("LSTM", nn.LSTM(d, h, batch_first=True)),
                  ("LSTM, f-bias 3", lstm_open)]:
    out, _ = rnn(x)                     # out: (1, T, h)
    out[0, -1].sum().backward()         # a "loss" that depends only on the last step
    g = x.grad[0].norm(dim=1)           # sensitivity of that loss to each input step
    print(f"{name:15s}", "  ".join(f"t={t}: {g[t].item():.0e}" for t in [99, 90, 75, 50, 25, 0]))
    x.grad = None

The output is the table in Section 10.3.

#Lab 10B: a character-level LSTM

import torch, torch.nn as nn, torch.nn.functional as F

torch.manual_seed(0)
text = open("input.txt").read()
chars = sorted(set(text)); V = len(chars)
stoi = {c: i for i, c in enumerate(chars)}
data = torch.tensor([stoi[c] for c in text])
n = int(0.9 * len(data)); train, val = data[:n], data[n:]

class CharLSTM(nn.Module):
    def __init__(self, V, d=128):
        super().__init__()
        self.emb = nn.Embedding(V, d)
        self.rnn = nn.LSTM(d, d, batch_first=True)
        self.head = nn.Linear(d, V)
    def forward(self, idx, state=None):
        h, state = self.rnn(self.emb(idx), state)     # h: (B, T, d)
        return self.head(h), state                    # logits: (B, T, V)

def get_batch(d, B=32, T=64):
    ix = torch.randint(len(d) - T - 1, (B,))
    return torch.stack([d[i:i + T] for i in ix]), torch.stack([d[i + 1:i + T + 1] for i in ix])

model = CharLSTM(V)
opt = torch.optim.Adam(model.parameters(), lr=3e-3)
for step in range(1001):
    x, y = get_batch(train)
    logits, _ = model(x)
    loss = F.cross_entropy(logits.reshape(-1, V), y.reshape(-1))
    opt.zero_grad(); loss.backward()
    nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    opt.step()
    if step % 250 == 0:
        with torch.no_grad():
            xv, yv = get_batch(val, B=256)
            lv = F.cross_entropy(model(xv)[0].reshape(-1, V), yv.reshape(-1))
        print(f"step {step:4d}  train {loss.item():.3f}  val {lv.item():.3f}")

Measured: the loss starts at 4.17, which is log 65, and validation loss reaches 1.96 at step 250 and 1.76 at step 1000. Note how the targets are built: y is x shifted by one position, so every position in every sequence is a training example for next-token prediction.
