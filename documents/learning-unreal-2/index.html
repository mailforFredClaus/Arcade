#1. What this project is and how to run it

Lake Highland Stray is a third-person Unreal Engine 5.8 game written entirely in C++: you play an orange tabby in a real Orlando neighborhood rebuilt from map, elevation, parcel and aerial data. A man feeds you at 7 AM and 7 PM, five strays have their own personalities, and a game day lasts 24 real minutes.

It was built code-first. Python and Blender scripts generate every mesh, texture and sound and even assemble the level, and the C++ module spawns the gameplay at startup. That makes it unusually readable for a C++ developer and a little unusual for Unreal, where most teams work in the editor; this walkthrough points out where the two styles differ. Read Part 1 first; section numbers like "Part 1 §5" refer to it.

GoalHow
PlayRun Build\Package\Windows\LakeHighlandStray.exe, then press Enter at the title screen
Open in the editorDouble-click LakeHighlandStray\LakeHighlandStray.uproject, then press Play (Alt+P). The first launch compiles shaders and can take several minutes
Debug the C++Right-click the .uproject > Generate Visual Studio project files, open the new LakeHighlandStray.sln in Visual Studio 2022 (installed on this PC), choose Development Editor, press F5
Rebuild after a C++ changeSmall .cpp edit with the editor open: Live Coding, Ctrl+Alt+F11. Header or class change: close the editor and build (below)
Run the automated testPipeline\ue\run_game.ps1 -Mode editor (uncooked) or -Mode packaged (the shipped build)

To build the editor module from a terminal, which is what the earlier sessions did:

#3. The project and build files

Four small text files tell Unreal what this project is and how to compile it (Part 1 §11). Read them in this order.

LakeHighlandStray.uproject names the engine version and the single C++ module, and enables three editor-only plugins. Trimmed, with annotations (real JSON has no comments):

{
  "EngineAssociation": "5.8",                       // which installed engine opens the project
  "Modules": [{ "Name": "LakeHighlandStray",         // the folder Source/LakeHighlandStray
                "Type": "Runtime",                   // ships in the game, not editor-only
                "AdditionalDependencies": ["Engine", "AIModule", "UMG"] }],
  "Plugins": [{ "Name": "PythonScriptPlugin",        "TargetAllowList": ["Editor"] },
              { "Name": "EditorScriptingUtilities",  "TargetAllowList": ["Editor"] },
              { "Name": "ModelingToolsEditorMode",   "TargetAllowList": ["Editor"] }]
}

Source\LakeHighlandStray\LakeHighlandStray.Build.cs lists the engine modules this module links against. Every engine module whose headers you include must appear here; a linker error about an unresolved engine symbol usually means one is missing.

PublicDependencyModuleNames.AddRange(new string[] {
    "Core", "CoreUObject", "Engine", "InputCore",
    "EnhancedInput",                    // UInputAction, UInputMappingContext
    "AIModule", "NavigationSystem",     // AAIController, navmesh queries for the strays
    "UMG", "Slate", "SlateCore",        // UI frameworks; the HUD measures text with Slate
    "RenderCore", "RHI",                // thread and GPU timings in the automated test
    "AudioMixer", "Json", "JsonUtilities" // Json parses world_meta.json
});
PublicIncludePaths.Add(ModuleDirectory + "/Public");

The two .Target.cs files each describe one executable built from the module. LakeHighlandStrayEditor.Target.cs (TargetType.Editor) produces UnrealEditor-LakeHighlandStray.dll, which the editor loads; LakeHighlandStray.Target.cs (TargetType.Game) produces the standalone game when you package. Both opt into UE 5.8's build defaults and header include order (BuildSettingsVersion.V7, EngineIncludeOrderVersion.Unreal5_8).

The module registration is one line in Private\LakeHighlandStray.cpp:

IMPLEMENT_PRIMARY_GAME_MODULE(FDefaultGameModuleImpl, LakeHighlandStray, "LakeHighlandStray");

It registers the DLL with the engine's module manager; a module that needs startup or shutdown code supplies its own class instead of FDefaultGameModuleImpl. Headers live in Public and implementations in Private, and the project's log category, LogLH, is declared in LHTypes.h and defined in LHWorldData.cpp.

Everything talks through the GameMode. Actors call Cast<ALHGameMode>(GetWorld()->GetAuthGameMode()), then read its pointers (Station, Man, Strays, DayNight, Player) or call its event functions (OnPlayerMeow, OnStrayGreeted, OnPlayerLanded). The GameMode reacts by telling other actors (the man hears a meow, wildlife scatters from a pounce) and by queuing messages the HUD draws. That mediator design is easy to follow in one level; larger Unreal projects usually decouple it with delegates or subsystems.

Read these first, in this order:

  1. LHGameMode.cpp: StartPlay, SpawnWorldSystems, SpawnStrays. The startup story; note SpawnActorDeferred plus FinishSpawningActor, which let it set each stray's personality and home before that stray's BeginPlay runs.

  2. CatCharacter.cpp, the constructor: components created with CreateDefaultSubobject, assets found by path, and the movement tuning from Part 1 §10.

  3. PlayerCat.cpp: InputMove, JumpPressed/JumpReleased and Tick. Input becomes movement requests, a held jump charges a leap, and Tick integrates hunger and energy.

  4. StrayCat.cpp: Think and ReactToPlayer. A readable AI state machine with no Behavior Tree, falling back to whisker-sweep steering when navigation fails.

  5. LHDayNight.cpp: SolarPosition and UpdateLighting. Standard solar-position equations drive the lights, the most simulation-like code in the project.

  6. BlendAnimInstance.cpp: animation from scratch. Advanced; skim it once you know what an Animation Blueprint normally does.

Unreal habits on display: assets referenced by path in constructors (ConstructorHelpers::FObjectFinder); UPROPERTY() on every actor pointer the GameMode keeps, so the garbage collector sees them; TWeakObjectPtr for references that may disappear (APlayerCat::FocusActor); #if WITH_EDITOR code that waits for shader compilation in uncooked test runs; and #if !UE_BUILD_SHIPPING around the GPU profiling hook.

What a typical studio would do differently: expose asset references as UPROPERTY(EditDefaultsOnly) members set in Blueprint subclasses or Data Assets, so an artist can swap a mesh without a recompile, and keep the stray roster in a Data Table rather than JSON. #7. One frame, traced: from the W key to a moving cat and a following camera

Holding W makes the cat trot forward relative to the camera. Here is what happens in one frame, in order, and where to find each step; Part 1 §6 covers the frame structure and §10 the systems involved.

  1. Input is queued. Windows delivers the key event, Slate routes it to the game viewport, and the player controller's input object holds it until the controller ticks.

  2. The controller ticks early in TG_PrePhysics, and Enhanced Input evaluates IMC_Cat. W maps to IA_Move through a swizzle modifier, so the key's 1D value becomes the 2D value (0, 1), and the Triggered event calls ALHPlayerController::OnMove. The mouse takes the same route through IA_Look.

  3. The controller hands intent to the pawn. OnMove checks that the game is in play and calls APlayerCat::InputMove, which leaves any sitting or eating pose, builds forward and right vectors from the controller's yaw (so movement is camera-relative) and calls AddMovementInput twice. Nothing moves yet; the requests accumulate.

  4. The cat's own Tick sets its speed. APlayerCat::Tick picks a target speed (85 cm/s sneaking, 360 trotting, 640 sprinting while energy lasts, a quarter slower when starving) and eases MaxWalkSpeed toward it with FInterpTo. It also integrates hunger and energy, charges a held jump, runs the ledge assist and the water and boundary checks, and refreshes the interaction prompt every 0.1 s.

  5. The movement component integrates. UCharacterMovementComponent turns the accumulated input into acceleration (up to 1,500 cm/s²), applies ground friction, clamps to MaxWalkSpeed, then sweeps the capsule along the new velocity, sliding along walls and stepping up to 26 cm. The engine makes the movement component tick after the controller, so this frame's input moves the cat this frame, and bOrientRotationToMovement turns the cat toward its heading at 600°/s.

  6. Animation follows the result. ACatCharacter::UpdateAnimation hands the new ground speed to UBlendAnimInstance, which blends the two locomotion clips that bracket it (walk at 95, trot at 300, run at 560 cm/s) with a shared phase so the paws stay in step. Head look-at and ear twitches are added as bone offsets, and the pose is evaluated where the engine can run it on a worker thread.

  7. Physics steps. Chaos advances simulated bodies; the cat is moved kinematically by its movement component, so it is not one of them.

  8. The camera catches up. The spring arm Boom follows the controller's rotation with lag (speed 11) and casts a 9 cm probe that pulls the camera in when something solid is between it and the cat; tree trunks don't count, thanks to LHFoliage. After all ticks, ALHPlayerController::UpdateCameraManager computes the final view and writes the camera-to-cat vector to MPC_LH.CatRel.

  9. The HUD draws on top. ALHHUD::DrawHUD reads the GameMode and the cat (needs, clock, and prompts such as "[E] Eat the crunchy kibble") and draws them with canvas calls.

  10. The image arrives a frame or two later. The render thread picks up the moved capsule and new bone transforms, the foliage material uses CatRel to dither away leaves on the line from camera to cat, and Lumen, virtual shadows and TSR finish the frame on the GPU.

#8. The tooling around the project

Every asset under /Game/LH, and the level itself, comes from scripts run in six stages. Each stage reads the files the previous one wrote, so any stage can be rerun alone; the README at the top of the folder lists the exact commands.

Stages 1 to 4 run outside Unreal in Python and Blender, the shaded stage runs inside the Unreal editor with no window, and the last stage produces and tests the game.

Editor Python is the Unreal skill on show here. The unreal module exposes most of the editor: EditorAssetLibrary loads and saves assets, AssetTools imports files, MaterialEditingLibrary builds material graphs, and EditorActorSubsystem spawns actors in a level. Reflection makes your own classes scriptable too: unreal.LHPropScatter is ALHPropScatter, and set_editor_property("transforms", ...) sets its UPROPERTY named Transforms. run_ue.ps1 runs a script with no window, essentially:

UnrealEditor-Cmd.exe LakeHighlandStray.uproject -run=pythonscript -script=<file.py> -unattended -nosplash -NoSound -stdout

The game tests itself. run_game.ps1 launches either the uncooked project (UnrealEditor.exe <project> /Game/Maps/LakeHighland -game) or the packaged build with -LHAutoTest, and ALHGameMode::TickAutoTest plays a scripted day. It teleports the cat, sets the clock, presses real keys through Slate, takes screenshots, logs LHTEST: lines and measurements to results.txt, then quits; -LHGallery runs LHGallery.cpp instead, posing shots and checking edge cases such as the pool splash, the fence leap and the play-area boundary.

Packaging is one Unreal Automation Tool call in package.ps1:

RunUAT.bat BuildCookRun -project=<uproject> -platform=Win64 -clientconfig=Shipping -build -cook -stage -pak -iostore -compressed -archive -archivedirectory=Build\Package

-build compiles the Game target, -cook converts every referenced asset for Windows, -stage lays files out as they will ship, -pak and -iostore bundle them into containers, and -archive copies the result to Build\Package\Windows.

#10. Hands-on exercises

Work through these in order; each builds on the one before. First copy LakeHighlandStray\Source somewhere safe (it is under 1 MB), or put the project under git with Binaries, Intermediate, Saved and DerivedDataCache ignored.

  • 1. Explore without code. Open the project, press Play, then press F8 to eject from the cat. Select the player cat in the Outliner and compare its components in the Details panel with the diagram in Part 1 §3; try stat unit and show collision in the console (~).

  • 2. Change a number with Live Coding. In PlayerCat.cpp, JumpReleased, change the full-charge launch speed 830.f to 1100.f. Stop Play, press Ctrl+Alt+F11, play again and hold Space: the full leap is now much higher.

  • 3. Add an on-screen readout. At the end of APlayerCat::Tick, add GEngine->AddOnScreenDebugMessage(1, 0.f, FColor::Yellow, FString::Printf(TEXT("Speed %.0f cm/s Hunger %.1f"), GetVelocity().Size2D(), Hunger));, plus #include "Engine/Engine.h" at the top. Live Coding handles it; check the trot, sprint and sneak speeds against section 7.

  • 4. Expose a value to the editor. In CatCharacter.h, put UPROPERTY(EditAnywhere, Category = "Cat|Movement") in front of float SprintSpeed = 640.f;. That is a header change, so close the editor, build (section 1) and reopen; then, during Play, eject, select the cat, set Sprint Speed to 1200 in Details, press F8 to take control again, and sprint.

  • 5. Debug with breakpoints. Generate the Visual Studio solution (section 1), choose DebugGame Editor, press F5, and set a breakpoint in AStrayCat::OnGreetedBy. Play, find Smokey (the friendly gray cat), press E beside it, and inspect Info.Hearts as you step.

  • 6. Watch the AI think. In AStrayCat::MoveTo, add DrawDebugLine(GetWorld(), GetActorLocation(), Target, FColor::Green, false, 3.f, 0, 2.f); with #include "DrawDebugHelpers.h". Green lines show each stray's next goal, and the console command show Navigation reveals navmesh tiles that exist only around the strays.

  • 7. Run a time-step experiment. Log the time from pressing Shift while standing still until speed passes 600 cm/s, at t.MaxFPS 15 and at t.MaxFPS 120. Then replace the FInterpTo line in APlayerCat::Tick with the exact blend CM->MaxWalkSpeed += (Target - CM->MaxWalkSpeed) * (1.f - FMath::Exp(-6.f * DeltaSeconds)); and compare again.

  • 8. Write a new actor. Add LHLaserDot.h and LHLaserDot.cpp from the starter code below and spawn one in ALHGameMode::SpawnWorldSystems. New files need a full build, and the Visual Studio solution must be regenerated before it lists them.

// A dot that circles where it was spawned: a minimal actor for practicing the lifecycle.
#pragma once

#include "CoreMinimal.h"
#include "GameFramework/Actor.h"
#include "LHLaserDot.generated.h"

class UStaticMeshComponent;

UCLASS(Blueprintable)
class LAKEHIGHLANDSTRAY_API ALHLaserDot : public AActor
{
	GENERATED_BODY()

public:
	ALHLaserDot();
	virtual void BeginPlay() override;
	virtual void Tick(float DeltaSeconds) override;

	UPROPERTY(VisibleAnywhere) TObjectPtr<UStaticMeshComponent> Dot;

	/** Circle radius (cm) and angular speed (deg/s). */
	UPROPERTY(EditAnywhere, Category = "Dot") float Radius = 150.f;
	UPROPERTY(EditAnywhere, Category = "Dot") float DegreesPerSecond = 90.f;

private:
	FVector Center = FVector::ZeroVector;
	float Angle = 0.f;
};

Private\LHLaserDot.cpp:

#include "LHLaserDot.h"

#include "Components/StaticMeshComponent.h"
#include "Engine/StaticMesh.h"
#include "UObject/ConstructorHelpers.h"

ALHLaserDot::ALHLaserDot()
{
	PrimaryActorTick.bCanEverTick = true;
	Dot = CreateDefaultSubobject<UStaticMeshComponent>(TEXT("Dot"));
	RootComponent = Dot;
	Dot->SetCollisionEnabled(ECollisionEnabled::NoCollision);
	Dot->SetRelativeScale3D(FVector(0.05f)); // the engine sphere is 100 cm across
	static ConstructorHelpers::FObjectFinder<UStaticMesh> Sphere(TEXT("/Engine/BasicShapes/Sphere.Sphere"));
	if (Sphere.Succeeded())
	{
		Dot->SetStaticMesh(Sphere.Object);
	}
}

void ALHLaserDot::BeginPlay()
{
	Super::BeginPlay();
	Center = GetActorLocation();
}

void ALHLaserDot::Tick(float DeltaSeconds)
{
	Super::Tick(DeltaSeconds);
	Angle = FMath::Fmod(Angle + DegreesPerSecond * DeltaSeconds, 360.f);
	const float R = FMath::DegreesToRadians(Angle);
	SetActorLocation(Center + FVector(FMath::Cos(R), FMath::Sin(R), 0.f) * Radius);
}
