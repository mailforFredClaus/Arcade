Chapter 8: Convolution and Inductive Bias

Objectives. After this chapter you can:

  • define a convolutional layer and compute its output shape and parameter count;

  • explain locality, weight sharing, and translation equivariance;

  • describe the structure of a modern convolutional network;

  • define inductive bias and explain the trade between built-in structure and data.

This chapter is shorter than its neighbors. Convolutional networks are not on the direct path to language models, but the idea they illustrate, that architecture is a way of telling the model what you already know, is essential for understanding why the Transformer looks the way it does.

8.1 Why not an MLP on pixels

A modest color image of 224 × 224 pixels has 150,528 input values. A first hidden layer of 1000 units would need 150 million weights, for one layer.

The waste is worse than the count suggests. An MLP treats its inputs as an unordered list. It does not know that two pixels are neighbors, and a detector learned for an edge in the top-left corner says nothing about the same edge in the bottom-right. The network would have to learn every feature separately at every position, from examples that happen to show it there.

8.2 The convolutional layer

A convolutional layer slides a small learned filter over the image and reports how well each neighborhood matches it. With input x of shape (C_in, H, W) and a kernel K of shape (C_out, C_in, k, k):

y[o, i, j] \;=\; b_o + \sum_{c=1}^{C_{\mathrm{in}}} \sum_{u=0}^{k-1} \sum_{v=0}^{k-1} K[o, c, u, v]\;\, x[c,\, i+u,\, j+v] .

Each output channel o is a map of where its filter's pattern occurs. Strictly this is cross-correlation; the name convolution has stuck.

Figure 8.1: the shaded window is multiplied entry by entry with the filter and summed to give the one shaded output value. Sliding the window to each of the 25 positions fills the feature map, always with the same nine weights.

Shapes and parameters. With stride s and zero padding p on each side, the output height is floor((H + 2p − k)/s) + 1, and likewise for width. The layer has C_out (C_in k² + 1) parameters. That count does not depend on the image size.

Three assumptions are built in.

  1. Locality. Each output depends only on a k × k neighborhood. Nearby pixels are assumed to be the ones that matter to each other.

  2. Weight sharing. The same filter is applied at every position. A feature worth detecting somewhere is assumed worth detecting everywhere.

  3. Translation equivariance. As a consequence, shifting the input shifts the output by the same amount: conv(shift(x)) = shift(conv(x)).

A convolutional layer is a special case of a linear layer: one whose weight matrix is mostly zeros, with the nonzero entries tied together in a repeating pattern (Problem 8.2). Everything in Chapter 5 applies unchanged. What changed is that the hypothesis space has been cut down to functions that respect the structure of images.

Pooling. A pooling layer summarizes each small window, usually 2 × 2, by its maximum or mean, halving the resolution. It gives a little invariance to small shifts and lets later layers see a larger region of the original image. The region of the input that can affect a given unit is its receptive field, and it grows with depth.

Checkpoint 8.1. A layer has 64 filters of size 3 × 3 over 32 input channels. How many parameters does it have? How many would a fully connected layer need to map a 32 × 56 × 56 input to a 64 × 56 × 56 output?

The common design is a sequence of stages. Each stage applies several convolutional blocks, then reduces spatial resolution and increases the number of channels. Spatial detail is traded for semantic content. A global average over the remaining positions feeds a final softmax layer.

Visualizing what the units respond to shows a hierarchy that nobody programmed: oriented edges and color blobs in the first layer, textures next, then object parts, then whole objects. It is the clearest picture available of learned features composing.

Transfer. Features learned on one large labeled dataset turned out to be useful for other visual tasks. One could take a network trained on ImageNet, replace its last layer, and fine-tune on a small dataset with good results. This pretrain-then-adapt pattern, discovered in vision, is the template that language models later followed at far greater scale.

8.4 Inductive bias

An inductive bias is any assumption built into a learner that makes it prefer some solutions over others before seeing data. Every learner has one. Without it, a finite dataset is consistent with infinitely many functions and there is no basis for choosing among them.

Architecture is the main place inductive bias lives.

ArchitectureWhat it assumesSymmetry respected
MLPNothing about input structureNone
Convolutional networkLocality; the same features matter everywhereTranslation
Recurrent network (Chapter 10)Inputs arrive in order; the same update applies at every stepShift in time
Transformer (Chapter 11)Almost nothing: any position may be relevant to any otherPermutation of positions, until position information is added as input

The trade. A strong bias that matches the data buys sample efficiency: the model does not have to spend examples learning what it was told. A strong bias that does not quite match becomes a ceiling. A weak bias needs more data to reach the same quality but can then learn structure that no designer anticipated.

Lab 8 shows the first half. With the same number of parameters and the same data, a convolutional network beats an MLP on small digit images, and when the test images are shifted by one pixel the MLP's accuracy collapses to 51 percent while the convolutional network holds 70.

The second half played out in research. When Transformers were applied to images cut into patches (the Vision Transformer, 2020), they lost to convolutional networks on datasets of a million images and matched or beat them when pretrained on hundreds of millions. With enough data, the model learned the regularities that convolution hard-codes, and was not limited by them.

This is the bitter lesson of Chapter 1 in architectural form, and it sets up Part III. The Transformer is the least constrained architecture in wide use. That is why it needed enormous data, and why, once the data was available, it displaced the alternatives.

Lab 8: convolution against a matched MLP

import torch, torch.nn as nn, torch.nn.functional as F
from sklearn.datasets import load_digits

torch.manual_seed(0)
digits = load_digits()
X = torch.tensor(digits.images, dtype=torch.float32).unsqueeze(1) / 16.0   # (1797, 1, 8, 8)
y = torch.tensor(digits.target)
perm = torch.randperm(len(X))
tr, te = perm[:1400], perm[1400:]

cnn = nn.Sequential(
    nn.Conv2d(1, 16, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),     # (16, 4, 4)
    nn.Conv2d(16, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),    # (32, 2, 2)
    nn.Flatten(), nn.Linear(32 * 2 * 2, 10),
)
mlp = nn.Sequential(nn.Flatten(), nn.Linear(64, 80), nn.ReLU(), nn.Linear(80, 10))

def shift(x, dx):                         # translate right by dx pixels, zero fill
    out = torch.zeros_like(x)
    out[..., dx:] = x[..., :x.shape[-1] - dx]
    return out

def acc(net, x, t):
    with torch.no_grad():
        return (net(x).argmax(1) == t).float().mean().item()

for name, net in [("MLP", mlp), ("CNN", cnn)]:
    opt = torch.optim.Adam(net.parameters(), lr=3e-3)
    for step in range(600):
        idx = tr[torch.randint(0, len(tr), (64,))]
        loss = F.cross_entropy(net(X[idx]), y[idx])
        opt.zero_grad(); loss.backward(); opt.step()
    n_params = sum(p.numel() for p in net.parameters())
    print(f"{name}: {n_params} params   test acc {acc(net, X[te], y[te]):.3f}   "
          f"shifted by 1 px {acc(net, shift(X[te], 1), y[te]):.3f}")
