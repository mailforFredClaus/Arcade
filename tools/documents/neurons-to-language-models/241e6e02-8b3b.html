Chapter 19: Interpretability

Objectives. After this chapter you can:

  • distinguish behavioral, representational, and mechanistic understanding of a network;

  • train a linear probe, with the controls needed to interpret it;

  • explain the difference between showing information is present and showing it is used;

  • describe a circuit, using induction heads as the example;

  • explain superposition and how sparse autoencoders address it;

  • state what interpretability can and cannot currently do.

19.1 A program nobody wrote

You have the complete source of your Chapter 12 model: the architecture and every one of its 816,512 weights. You do not know how it decides that a speaker's name should come next. Training produced an algorithm, and nobody has read it.

The situation resembles having a compiled binary with no source code. Interpretability is the reverse engineering. Its motivations are scientific curiosity, debugging, and the verification problem of Section 17.7: if behavior cannot be exhaustively tested, perhaps the mechanism can be inspected.

19.2 Levels of understanding

LevelQuestionTypical method
BehavioralWhat does the model do on these inputs?Evaluation (Chapter 17)
AttributionalWhich parts of the input influenced this output?Gradients with respect to inputs; attention maps
RepresentationalWhat information is encoded in the activations?Probes
MechanisticWhat algorithm do the weights implement?Circuit analysis; causal interventions

A warning about the second row. Attention weights are tempting to read as explanations, since they say where a head "looked". They are one factor in a product. A head can attend strongly to a position and copy almost nothing from it if the value vector there is small, and later layers can undo what it wrote. Treat attention maps as clues.

19.3 Features as directions

The working hypothesis of most interpretability research is that a network represents a feature, some property of the input that is useful downstream, as a direction in activation space. The value of the feature is the projection of the activation onto that direction. This is the linear representation hypothesis.

The evidence is cumulative. Word embeddings showed semantic relations as consistent vector offsets (Section 9.6). Linear probes, below, recover many properties from activations. Adding a feature's direction to the residual stream during a forward pass shifts the model's behavior in the corresponding way, which is called steering.

The residual stream of Section 11.7 is where these directions live. Because every layer reads from and writes to the same stream by linear maps, a direction written by one layer can be read by any later one. Applying the unembedding matrix directly to the stream at an intermediate layer, a technique called the logit lens, shows the model's running guess at the next token forming as depth increases.

19.4 Probing

A probe is a small model, usually linear, trained to predict some property from the frozen activations at one layer. If a linear probe succeeds on held-out data, the property is linearly decodable from that layer.

Lab 19 probes your Chapter 12 model for a quantity it was never given: the number of characters since the last line break. The token at a position does not contain this. The position embedding encodes position in the context window, not in the line. To have it, the model must compute it.

The model built a counter for position within the line, because knowing it helps predict where the line will end. Nobody asked it to. Toward the output the quantity becomes less linearly accessible, as the stream is converted into a prediction of the next character.

Two cautions, both essential.

Controls. A probe's success can reflect the probe more than the model. The second row is the control: the same probe on an untrained model of the same architecture gets about 0.23 at every layer, from what the raw tokens and positions give away. The trained model's 0.89 is meaningful against that baseline. Without a control, a probing result is uninterpretable.

Decodable is not the same as used. A probe shows that information is present. It does not show that the model's later computation relies on it. That requires intervention.

Notable results from probing. A Transformer trained only on sequences of moves in the board game Othello, with no board ever shown, develops an internal representation of the board state that a probe can read, and editing that representation changes the moves the model makes in the corresponding way (Li and others, 2022; Nanda and others, 2023). Language models have been found to carry linear representations of the geographic location of places and the dates of events (Gurnee and Tegmark, 2023).

19.5 Causal interventions

To show that a component matters, change it and observe the output.

InterventionProcedureShows
AblationReplace a component's output with zero, or with its average valueWhether the component is necessary for the behavior
Activation patchingRun the model on a clean input and on a corrupted one. Copy one activation from the clean run into the corrupted runWhether that activation carries the information that distinguishes the two inputs
SteeringAdd a feature's direction to the residual streamWhether the feature is sufficient to change behavior

Every head contributes, none is indispensable, and the first layer matters most, with one head accounting for the largest single effect. This is typical: computation in trained networks is distributed and partly redundant.

Setting an output to zero puts the network in a state it never saw in training, which can exaggerate or distort effects. Replacing with the mean output, or patching from a different input, is more faithful.

19.6 Circuits

A circuit is a set of components, such as attention heads and MLP neurons, together with the connections among them, that implements an identifiable algorithm.

The best-understood example is the induction circuit (Elhage and others, 2021; Olsson and others, 2022). Its job: if the sequence so far contains ... A B ... and the current token is A again, predict B. It takes two attention heads in two different layers.

  1. A previous-token head in an early layer. At every position it attends to the position immediately before and copies that token's identity into the current position's stream. After this, the position holding B also carries the note "my predecessor was A".

  2. An induction head in a later layer. At the current token A, its query asks for a position whose predecessor was A. That matches the key at the old B position, thanks to the note left by the first head. The head attends there and copies B's identity into the current stream, raising the logit for B.

Figure 19.1: two attention heads in different layers compose. The first leaves a note on B about the token before it. The second uses that note to find B from the later A, and copies it forward as the prediction.

The two heads compose through the residual stream: the first writes what the second's keys read. Neither does anything useful alone.

Induction heads form abruptly during training, at a moment that coincides with a sharp improvement in the model's ability to use patterns from its context. They are a concrete mechanism for the simplest kind of in-context learning (Section 13.6). Problem 11.9 asked you to design this circuit. Gradient descent finds it unaided.

Other circuits have been worked out in comparable detail: how a small language model identifies the indirect object of a sentence (Wang and others, 2022), and how a small network performs modular addition using trigonometric identities that it discovers on its own (Nanda and others, 2023).

19.7 Superposition

The natural first guess is that each neuron represents one feature. It is wrong. Individual neurons in language models typically respond to several unrelated things. They are polysemantic.

The leading explanation is superposition (Elhage and others, 2022). A layer with d dimensions has only d orthogonal directions, but it has vastly more directions that are nearly orthogonal. If most features are inactive most of the time, the model can assign features to nearly orthogonal directions, many more of them than d, and tolerate the small interference that arises when two happen to be active together. The network is simulating a larger, sparser network than its dimension allows.

Figure 19.2: with more features than dimensions the directions cannot all be orthogonal. The price is interference between features, which stays small as long as the features are rarely active together.

This has a methodological consequence. If features are directions that do not line up with individual neurons, examining neurons one at a time is examining the wrong basis.

19.8 Sparse autoencoders

A sparse autoencoder (SAE) tries to recover the feature directions from the activations themselves. Collect a large set of activation vectors x from one layer. Train a one-hidden-layer network to reconstruct each x through a much wider layer, with a penalty that keeps most of that layer's units at zero:

f = \mathrm{ReLU}(W_e\, x + b_e), \qquad \hat x = W_d\, f + b_d, \qquad L = \lVert x - \hat x \rVert^2 + \lambda\, \lVert f \rVert_1 .

Here f has many more entries than x. The reconstruction term forces the columns of W_d to span the activations. The sparsity term forces each activation to be explained by a few columns. The columns of W_d are the candidate features: a dictionary of directions.

In practice many of the learned features are far more interpretable than neurons. A feature may activate specifically on mentions of a particular landmark, on a kind of code error, or on text in a particular script, across languages and phrasings (Cunningham and others, 2023; Bricken and others, 2023). The approach has been scaled to production models with millions of features (Templeton and others, 2024). Clamping a feature to a high value steers the model: fixing a landmark feature on makes the model bring the landmark into unrelated conversations. More recent work links features across layers into graphs that trace how a specific output was computed.

Limits.

  • Reconstruction is imperfect. Part of every activation is left unexplained, and it is not known what that part does.

  • The features found depend on the size of the dictionary and on training choices. A feature in a small dictionary splits into several in a larger one.

  • Labels for features are assigned by people or other models looking at examples, and can be wrong.

  • It is not established that these features are the variables the model itself computes with, as opposed to a convenient description.

19.9 Where the field stands

An honest summary: interpretability can explain complete algorithms in small or toy models, and isolated pieces of behavior in large ones. It can find and manipulate many individual features. It cannot yet take an arbitrary model and certify what it will do, or reliably detect a specified property such as whether a statement the model made reflects what it internally represents as true. Whether the approach will scale to that is one of the open questions on which the verification problem of Chapter 17 depends.

Lab 19: a probe and an ablation

Needs gpt.py and gpt.pt from Chapter 12.

import math, torch, torch.nn.functional as F
from gpt import GPT, Config

torch.manual_seed(0)
text = open("input.txt").read()
chars = sorted(set(text)); stoi = {c: i for i, c in enumerate(chars)}
data = torch.tensor([stoi[c] for c in text])
val = data[int(0.9 * len(data)):]
cfg = Config(vocab_size=len(chars))
trained = GPT(cfg); trained.load_state_dict(torch.load("gpt.pt")); trained.eval()
random_init = GPT(cfg).eval()

# ---------- Part 1: a linear probe ----------
# Target: how many characters since the last newline (capped at 40)?
# The token at a position does not contain this; the model must compute it.
T = cfg.block_size
starts = torch.arange(0, len(val) - T, T)[:400]
X = torch.stack([val[s:s + T] for s in starts])                    # (400, T)
since = torch.zeros_like(X)
for b in range(X.shape[0]):
    c = 0
    for t in range(T):
        c = 0 if X[b, t] == stoi["\n"] else c + 1
        since[b, t] = min(c, 40)
keep = torch.zeros(X.shape[0], T, dtype=torch.bool)                # only positions whose line start is visible
for b in range(X.shape[0]):
    nl = (X[b] == stoi["\n"]).nonzero()
    if len(nl): keep[b, nl[0, 0]:] = True

@torch.no_grad()
def residual_streams(model, idx):
    """Residual stream after the embedding and after each block: list of (B, T, d)."""
    x = model.tok_emb(idx) + model.pos_emb(torch.arange(idx.shape[1]))
    out = [x]
    for blk in model.blocks:
        x = blk(x); out.append(x)
    return out

def probe_r2(acts, y, lam=1e-2):
    """Fit ridge regression on half the examples; report R^2 on the other half."""
    A = torch.cat([acts, torch.ones(len(acts), 1)], dim=1); y = y.float()
    n = len(A) // 2
    w = torch.linalg.solve(A[:n].T @ A[:n] + lam * torch.eye(A.shape[1]), A[:n].T @ y[:n])
    resid = y[n:] - A[n:] @ w
    return 1 - (resid ** 2).sum().item() / ((y[n:] - y[n:].mean()) ** 2).sum().item()

perm = torch.randperm(int(keep.sum()))
y = since[keep][perm]
for name, model in [("trained", trained), ("random init", random_init)]:
    r2 = [probe_r2(h[keep][perm], y) for h in residual_streams(model, X)]
    print(f"{name:12s} R^2 by layer (embedding, then after blocks 1-4): " + "  ".join(f"{v:.2f}" for v in r2))

# ---------- Part 2: ablating attention heads ----------
@torch.no_grad()
def loss_with_head_removed(model, idx, targets, layer=None, head=None):
    H, d = cfg.n_head, cfg.d_model
    B, T = idx.shape
    x = model.tok_emb(idx) + model.pos_emb(torch.arange(T))
    for l, blk in enumerate(model.blocks):
        q, k, v = blk.attn.qkv(blk.ln1(x)).split(d, dim=2)
        heads = lambda z: z.view(B, T, H, d // H).transpose(1, 2)
        q, k, v = heads(q), heads(k), heads(v)
        att = (q @ k.transpose(-2, -1)) / math.sqrt(d // H)
        att = F.softmax(att.masked_fill(~blk.attn.mask[:T, :T], float("-inf")), dim=-1)
        y = att @ v                                               # (B, H, T, d/H): one output per head
        if l == layer:
            y[:, head] = 0.0                                      # the intervention
        x = x + blk.attn.proj(y.transpose(1, 2).contiguous().view(B, T, d))
        x = x + blk.mlp(blk.ln2(x))
    logits = model.head(model.ln_f(x))
    return F.cross_entropy(logits.view(B * T, -1), targets.view(B * T)).item()

Xa = torch.stack([val[s:s + T] for s in starts[:100]])
Ya = torch.stack([val[s + 1:s + T + 1] for s in starts[:100]])
base = loss_with_head_removed(trained, Xa, Ya)
print(f"baseline loss {base:.3f}; increase in loss when one head is removed:")
for l in range(cfg.n_layer):
    print(f"  layer {l + 1}: " + "  ".join(
        f"{loss_with_head_removed(trained, Xa, Ya, l, h) - base:+.3f}" for h in range(cfg.n_head)))
