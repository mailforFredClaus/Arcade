Preface

A large language model is a function that maps a sequence of tokens to a probability distribution over the next token, with parameters chosen by stochastic gradient descent to minimize cross-entropy on a very large text corpus. This book exists to make every word of that sentence precise, and then to ask why such a plain recipe produces systems that write code, prove lemmas, and hold a conversation.

Who this is for. A reader with a graduate engineering or computational science background: comfortable with linear algebra, multivariable calculus, probability, numerical methods, and Python. No prior machine learning is assumed. Chapter 2 refreshes the mathematics in the form deep learning uses it.

The through-line. Three ideas carry the whole subject:

  1. A model is a parameterized, differentiable function. Architecture is the choice of which functions are easy to express.

  2. A loss scores the model against data. Almost every loss in this book is a negative log-likelihood.

  3. An optimizer follows the gradient of the loss, computed exactly and cheaply by reverse-mode automatic differentiation.

Everything else is either a refinement of one of these three or engineering to make them work at scale. The book builds them in order: one neuron, then a network, then the machinery to train it, then the architectural step (attention) that made language tractable, then the scale-up that produced modern LLMs.

What is deliberately left out. Product specifics, API documentation, and model leaderboards change monthly and are omitted. Classical machine learning (kernels, trees, graphical models) appears only where it illuminates neural networks. Reinforcement learning appears only where LLM training uses it.

A note on honesty. Parts of this field are engineering practice without settled theory. Where a claim is a theorem, the text says so. Where it is an empirical regularity or a working hypothesis, the text says that instead. The final chapter collects the open questions.

How to use this book

Treat this as a 16-week course at 6 to 8 hours a week. Reading alone will not produce the skill; the labs and problems are where the material becomes yours.

Every chapter has the same shape.

  1. Objectives. What you should be able to do afterward. Read them first and again at the end.

  2. Text. Derivations are given in full where they matter. Work them on paper alongside.

  3. Checkpoints. Short questions set off in block quotes. Answer each before reading on. If you cannot, reread the preceding section.

  4. Lab. Code you write and run. Type it; do not paste it. Every listing in this book was executed before it was included.

  5. Problems. One star is routine, two stars need thought, three stars are open-ended. Problems marked (A) have a hint or solution in Appendix A.

  6. Further reading. Primary sources, by author and title.

Software. Python 3.10 or later with numpy and matplotlib through Chapter 5, and PyTorch from Chapter 6 onward. Every lab runs on a laptop CPU. A GPU shortens Chapter 12 from about half an hour to a few minutes.

Notation

Inline mathematics is written in plain text, as in W ∈ R^(m×n) or h^(l). Displayed equations are typeset. Subscripts index elements, examples, or time steps; a superscript in parentheses indexes the layer.

SymbolMeaning
x, yInput and target. Scalars, vectors, or tensors by context. Vectors are columns in the mathematics
θAll trainable parameters, collected into one vector
W, bA weight matrix and a bias vector
f_θ(x), or f(x; θ)The model: a function of the input, parameterized by θ
ŷThe model's prediction
L(θ)The training loss, a scalar
ℓ(ŷ, y)The per-example loss
∇_θ LThe gradient of L with respect to θ. It has the same shape as θ
∂y/∂xThe Jacobian of y with respect to x, of shape (dim y) × (dim x)
ηLearning rate
σ(·)The logistic sigmoid, unless stated otherwise
⊙Elementwise product
p(y ∣ x; θ)Conditional probability of y given x under the model
E[·], Var[·]Expectation and variance
H(p), H(p, q), KL(p ‖ q)Entropy, cross-entropy, Kullback–Leibler divergence
logNatural logarithm, unless a base is given
NNumber of training examples
BBatch size
TSequence length, in tokens
VVocabulary size
dModel width: the dimension of each token's vector
L (as a count), HNumber of layers; number of attention heads. Context separates the layer count from the loss
x_(1:T), x_(<t)The sequence x_1, ..., x_T; the prefix before position t
1[·]Indicator: 1 if the condition holds, else 0

Math versus code. The mathematics uses column vectors, so a linear layer is y = Wx + b. Code stores a batch as rows, with shape (B, d), so the same layer is y = x @ W.T + b. Sequence tensors have shape (B, T, d), batch first. When a shape matters, the text states it.
