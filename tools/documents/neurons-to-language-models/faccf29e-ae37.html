14.1 A base model continues documents

The product of pretraining is called a base model. It is a model of documents. Give it the text "What is the capital of France?" and it will continue the document it guesses it is in. That might be an answer. It might equally be a second quiz question, or a forum reply complaining that the question is too easy.

A base model has the knowledge an assistant needs and none of the role. Three things are missing: the convention that it is in a dialogue and should respond to the last message; a consistent disposition to be helpful, accurate, and careful; and whatever specialized skills an application calls for. Adaptation supplies them.

14.2 Fine-tuning

Fine-tuning means continuing gradient descent from the pretrained weights on a new, smaller dataset, usually with a learning rate ten to a hundred times lower than in pretraining. The loss is still next-token cross-entropy.

It works because pretraining has already built general features, and the new data only needs to adjust how they are used. It has two characteristic risks. With little data the model overfits. And as the weights move to fit the new distribution they can lose abilities that the new data does not exercise, which is called catastrophic forgetting. A low learning rate, few passes, and the parameter-efficient methods of Section 14.5 all limit both.

14.3 Instruction tuning and the chat format

To make an assistant, fine-tune on transcripts of the behavior you want. Each training example is a conversation rendered into one token sequence, with special tokens marking who is speaking. The details vary between model families; a generic template looks like this:

<|system|>You are a helpful assistant.<|end|>
<|user|>What is the capital of France?<|end|>
<|assistant|>Paris.<|end|>

Training on many such examples is called supervised fine-tuning (SFT) or instruction tuning. The loss is usually computed only on the assistant's tokens, since those are what the model should learn to produce.

Nothing about the model has changed in kind. It is still predicting the next token. But the documents it now predicts are dialogues in which an assistant responds helpfully, so predicting the next token after the assistant marker means writing a helpful response. The assistant is, in a precise sense, a character the model has learned to write.

This view explains several things at once.

  • A system prompt is ordinary text at the start of the transcript. It influences behavior the same way any context does, strengthened by training examples in which the assistant follows such instructions.

  • The model generates until it emits the end-of-turn token. Stopping is a prediction like any other.

  • The assistant's stated beliefs about itself are part of the character and come from training data. They are not readouts of its internals.

  • Carefully constructed inputs can sometimes pull the model out of the assistant pattern and back toward generic document continuation, which is one root of the security problems in Chapter 17.

14.4 Learning from preferences

Supervised fine-tuning teaches imitation of demonstrations. That has limits. Writing an ideal response is expensive, while judging which of two responses is better is cheap. And imitation cannot exceed the demonstrations. Preference-based methods address both.

Reinforcement learning from human feedback (RLHF), as used for the first widely deployed chat assistants (Ouyang and others, 2022), has three stages.

Stage 1: collect comparisons. For each prompt x, sample several responses from the model and have people indicate which they prefer.

Stage 2: fit a reward model. Train a network r_φ(x, y) to output a scalar score, such that preferred responses score higher. Modeling the probability that y_w is preferred to y_l as a sigmoid of the score difference gives the loss

L(\phi) \;=\; -\,\mathbb{E}\Big[\log \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big)\Big].

This is logistic regression (Section 3.3) on score differences.

Stage 3: optimize the model against the reward. Treat the language model as a policy π_θ and adjust it to produce responses the reward model scores highly, while penalizing departure from the starting model π_ref:

\max_\theta \;\; \mathbb{E}_{x,\; y \sim \pi_\theta(\cdot \mid x)}\big[r_\phi(x, y)\big] \;-\; \beta\, \mathrm{KL}\big(\pi_\theta(\cdot \mid x)\,\big\|\,\pi_{\mathrm{ref}}(\cdot \mid x)\big).

Because sampling a response is not differentiable, this is optimized with a policy-gradient reinforcement learning algorithm.

Figure 14.1: each stage uses a different kind of data. Only the first needs people to write answers. The second needs only their judgments, and the third needs no new human data at all.

Why the KL penalty is essential. The reward model is a learned approximation, accurate only for responses resembling those it was trained on. An optimizer with no constraint will find responses that the reward model scores highly for wrong reasons. This failure, exploiting the errors of a learned objective, is a general hazard in machine learning and is discussed again in Chapter 17. The penalty keeps the policy in the region where the reward model can be trusted.

Direct preference optimization (DPO; Rafailov and others, 2023) reaches the same optimum without a separate reward model or reinforcement learning. The KL-constrained problem has a closed-form relation between the optimal policy and the reward. Substituting it into the reward-model loss gives an objective on the policy itself:

L_{\mathrm{DPO}}(\theta) = -\,\mathbb{E}\left[\log \sigma\!\left(\beta\Big[\log\frac{\pi_\theta(y_w \mid x)}{\pi_{\mathrm{ref}}(y_w \mid x)} - \log\frac{\pi_\theta(y_l \mid x)}{\pi_{\mathrm{ref}}(y_l \mid x)}\Big]\right)\right].

It raises the probability of the preferred response relative to the reference model, and lowers that of the rejected one. It is an ordinary supervised loss on pairs, which makes it simple and stable, and it is widely used.

Other sources of signal. Human comparisons are one source of reward. Others include written principles applied by a model acting as judge, and automatically checkable outcomes such as whether generated code passes its tests or a mathematical answer is correct. The last kind is central to training models that reason at length (Chapter 16).

Side effects. The model learns what the feedback rewards, which is not identical to what is true or good. If raters prefer confident, agreeable answers, the model becomes confident and agreeable, including when it should not be. Flattery of the user's stated views, called sycophancy, is a documented result. So are excessive hedging and unnecessary refusals when raters penalize risk.

14.5 Parameter-efficient fine-tuning: LoRA

Full fine-tuning updates every weight, so each adapted version is a complete copy of the model. For a model of tens of billions of parameters that is costly to train and store.

Low-rank adaptation (LoRA; Hu and others, 2021) freezes the pretrained weight matrix W_0 ∈ R^(m×n) and learns only a low-rank correction to it:

W \;=\; W_0 + \frac{\alpha}{r}\, B A, \qquad B \in \mathbb{R}^{m \times r}, \quad A \in \mathbb{R}^{r \times n}, \quad r \ll \min(m, n).

Only A and B are trained. A starts random and B starts at zero, so the correction is zero at the start and the adapted model initially equals the pretrained one.

Figure 14.2: the input takes both paths and the two results are added. Only A and B receive gradient updates.

The savings. The correction has r(m + n) parameters against mn for the full matrix. For a 4096 × 4096 matrix and r = 8, that is 65,536 against 16.8 million, or 0.4 percent. The frozen weights need no gradient storage or optimizer state.

No inference cost. After training, compute W_0 + (α/r)BA once and store it as an ordinary matrix. The adapted model has exactly the architecture and speed of the original. Alternatively keep the adapters separate, a few megabytes each, and swap them over one shared base model.

Why it works. By Eckart-Young (Section 2.1) a rank-r matrix is the best approximation to a general matrix that r directions allow. LoRA bets that the change needed to adapt a pretrained model is approximately low-rank. Empirically this holds well when the new task is close to what the model already does, and less well for large shifts.

Lab 14 applies LoRA to the attention matrices of your Chapter 12 model, adapting it to the same plays written entirely in capital letters. The base model's loss on that text is 4.50, worse than a uniform guess, because it is confidently wrong. Training 24,576 adapter parameters, 2.9 percent of the total, for 300 steps brings it to 1.96.

14.6 Distillation

Knowledge distillation (Hinton, Vinyals, and Dean, 2015) trains a small student model to reproduce the behavior of a large teacher. The student is trained to match the teacher's full output distribution, softened by a temperature τ, in place of or alongside the one-hot target:

L \;=\; \tau^2\, \mathrm{KL}\Big(\operatorname{softmax}(z^{\mathrm{teacher}}/\tau)\;\Big\|\;\operatorname{softmax}(z^{\mathrm{student}}/\tau)\Big).

The teacher's distribution carries far more information per example than a single correct label. It says which wrong answers are nearly right. A student trained on these soft targets typically does better than the same network trained on the data directly.

For LLMs a second form is common: generate a large corpus of responses from the teacher and fine-tune the student on it as ordinary text. Small, fast models offered alongside large ones are often produced this way.

14.7 Quantization

Quantization stores each weight in fewer bits. A block of weights is mapped to integers on a uniform grid:

w \;\approx\; s \cdot q, \qquad q = \operatorname{round}(w / s) \in \{-2^{b-1}, \dots, 2^{b-1} - 1\},

with a scale s chosen per block. Going from 16 bits to 8 or 4 cuts memory by a factor of 2 or 4, and memory is usually the binding constraint for running a model on modest hardware. At 4 bits a model with 7 billion parameters occupies 3.5 gigabytes.

Networks tolerate this well, because trained weights are noisy to begin with and the function they compute is robust to small perturbations. As a rule, 8 bits loses almost nothing, 4 bits loses a little with a careful method, and below that quality falls quickly. Quantizing after training is simplest. Simulating quantization during training gives better results at very low precision.

14.8 Choosing a method

What you needFirst thing to try
A one-off task or a format changeA better prompt (Chapter 16)
Knowledge that is private, recent, or changes oftenRetrieval (Chapter 16), not fine-tuning
A consistent style, tone, or output structureSupervised fine-tuning, usually with LoRA
Behavior that is easier to judge than to demonstratePreference optimization
Lower cost or latency at similar qualityDistillation into a smaller model; quantization
A capability the base model lacks entirelyA stronger base model

The usual order of escalation is prompt, then retrieval, then fine-tuning. Each step costs more and is harder to change afterward.

Lab 14: LoRA

This lab needs gpt.py and the trained weights gpt.pt from Chapter 12.

import math, torch, torch.nn as nn, torch.nn.functional as F
from gpt import GPT, Config

class LoRALinear(nn.Module):
    """Wraps a frozen nn.Linear and adds a trainable low-rank update: W + (alpha/r) B A."""
    def __init__(self, base, r=8, alpha=16):
        super().__init__()
        self.base = base
        for p in self.base.parameters():
            p.requires_grad = False
        self.A = nn.Parameter(torch.randn(r, base.in_features) / math.sqrt(base.in_features))
        self.B = nn.Parameter(torch.zeros(base.out_features, r))     # zero: no change at start
        self.scale = alpha / r
    def forward(self, x):
        return self.base(x) + self.scale * (x @ self.A.T) @ self.B.T
    def merge(self):                         # fold the update into the base weight
        self.base.weight.data += self.scale * self.B @ self.A
        return self.base

if __name__ == "__main__":
    torch.manual_seed(0)
    text = open("input.txt").read()
    chars = sorted(set(text)); stoi = {c: i for i, c in enumerate(chars)}
    data = torch.tensor([stoi[c] for c in text.upper()])           # the new "domain": all capitals
    n = int(0.9 * len(data)); train, val = data[:n], data[n:]

    cfg = Config(vocab_size=len(chars))
    model = GPT(cfg); model.load_state_dict(torch.load("gpt.pt")); model.eval()

    def get_batch(d, B=32):
        ix = torch.randint(len(d) - cfg.block_size - 1, (B,))
        return (torch.stack([d[i:i + cfg.block_size] for i in ix]),
                torch.stack([d[i + 1:i + 1 + cfg.block_size] for i in ix]))

    @torch.no_grad()
    def val_loss():
        return sum(model(*get_batch(val))[1].item() for _ in range(10)) / 10

    x, _ = get_batch(val, 4)
    before = model(x)[0]
    print(f"base model on capitals: val loss {val_loss():.3f}")

    for p in model.parameters():
        p.requires_grad = False
    for blk in model.blocks:                                       # adapt attention only
        blk.attn.qkv = LoRALinear(blk.attn.qkv)
        blk.attn.proj = LoRALinear(blk.attn.proj)
    print("unchanged at init:", torch.allclose(before, model(x)[0], atol=1e-5))

    trainable = [p for p in model.parameters() if p.requires_grad]
    total = sum(p.numel() for p in model.parameters())
    print(f"trainable {sum(p.numel() for p in trainable):,} of {total:,} "
          f"({100 * sum(p.numel() for p in trainable) / total:.1f}%)")

    opt = torch.optim.AdamW(trainable, lr=1e-3, weight_decay=0.0)
    for step in range(301):
        _, loss = model(*get_batch(train))
        opt.zero_grad(); loss.backward(); opt.step()
        if step % 100 == 0:
            print(f"step {step:3d}  val loss {val_loss():.3f}")

    after = model(x)[0]
    for blk in model.blocks:
        blk.attn.qkv = blk.attn.qkv.merge(); blk.attn.proj = blk.attn.proj.merge()
    print("merged equals adapted:", torch.allclose(after, model(x)[0], atol=1e-4))
